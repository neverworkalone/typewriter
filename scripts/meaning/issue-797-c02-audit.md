## Detection rule

A source homonym number is two ASCII digits written directly after a Korean headword and immediately
followed by a reference boundary: a closing quote, the end of the gloss, whitespace, `.`, `,`, a
bracket marker (`[1]`, `[Ⅰ]`) or a sense marker (`「1」`). A digit run that is followed by a counter,
unit or any other letter is a real number and never matches, so the audit did not apply a blanket
`text + two digits` replacement:

| gloss fragment | why it is not a source number |
| --- | --- |
| `높이는 60~90cm이며` | measurement |
| `삭과(蒴果)로 9월에 익는다` | date |
| `몸의 길이는 1.5cm 정도이며` / `1.2~1.5cm` | measurement |
| `줄기는 높이가 50~100cm이고` | measurement |
| `높이는 15미터 정도이며` | measurement |
| `제20대 대통령`, `제23대 왕(1192~1259)` | ordinal rank (`제` + number + counter) |
| `제40조는`, `제16회 국제 연합 총회`, `제25품(品)` | ordinal rank / article / volume number |
| `4개의 꼬리뼈`, `5~6월에 산란한다` | quantity / date |

C02 has no unclassified digit context: all 80 `Hangul + exactly two digits` occurrences are STDICT
homonym references, and all other digit contexts are covered by the preserved categories above.

## `→` reference linking

Issue #797 decided that a `→` reference is not only a number-removal target: the referencing Meaning must be
linked to the correct **target Meaning** through the existing synonym (`direct`) relation, durably, so the
product shows a working synonym target instead of a source identifier.

Every C02 `→` reference was resolved from the raw STDICT source record, which preserves the exact target of a
redirect as structured data (`definition_original`, e.g. `→ <sense_no>489793</sense_no>까치발_.` /
`→ <word_no>383277</word_no>가라앉다_.`). The resolution is therefore source-bound, not string matching:

- **`<sense_no>` (176 references)** names one source sense; the target is the Meaning that lists that sense.
- **`<word_no>` (97 references)** names the source *headword* (homonym) only. When that homonym is realized as
  one Meaning the target is that Meaning (74 references). When it is realized as several separate Meanings the
  owner decision for this issue is to link the **first (representative) Meaning** of the referenced headword
  (23 references); the candidates are listed below.
- Every chosen target Meaning carries exactly the referenced headword as its `lemma` (verified row by row), and
  the target Meaning is added with `type = direct`, `note = 표준국어대사전 참조 표제어`, committed on the
  meaning row in `data/meanings/` and projected with `origin = typewriter-authored`. No generated SQLite is
  edited.

### Number-removal display collapse audit

The same check audits the other half of the contract the Issue #797 review asked for: removing the number must not
collapse independently bound Meanings into one display. It groups every stored Meaning by lemma and exact gloss and
reports a group whose members (a) bind to different canonical source glosses and (b) display exactly their source
gloss with the homonym numbers removed. Such a group passes only when every member already resolves to the same
target Meaning, which is the pre-existing `#764`/`#772` Meaning-normalization case (a duplicate display, not a lost
distinction); otherwise it fails the completed scope.

Corpus-wide the audit finds exactly one such group, and it is the tolerated type — the `깨이다` pair the review
itself retracted (`m53954`/`m53955`, source `→ 깨다03.` / `→ 깨다05.`, one shared target Meaning `m54685_1`).
The other shape, an identical display whose members resolve to different targets or to none at all, is a
violation; that is exactly the `뀌다` `m57851`/`m57852` state before the fix below, and the regression test
`tests/meaning-arrow-links.test.mjs` ("number removal that collapses distinct source meanings fails a completed
scope") reproduces both shapes. C02 therefore reports `display_collapses: 1`, `display_collapses_tolerated: 1`,
`completed_scope_collapse_violations: 0`.

### Target Meaning id durability across re-partitions

An authored relation names a target Meaning id, and another scope's `#764` re-partition can move that id. When this
PR was rebased onto current master (`cf73dd4a`, the C01/C08/C10/C17/C19 re-edits), `scripts/meaning/validate.mjs`
failed closed on exactly one relation: `꼬실꼬실` `m55199` (`→ 고슬고슬.`) still pointed at `m396544`, whose source
sense `w396544-s1` the C01 re-edit had merged into the new Meaning `m25428` (`sense_ids` `w25428-s1`,
`w396544-s1`). The edit spec now re-points it through the same `apply-edits` `relations` key — `remove` the stale
target, `add` `m25428` — so the durable path covers re-targeting instead of needing a hand edit, and re-applying
the spec after the re-point is a no-op. The 272 other targets were unchanged, the reference text is unchanged
(`→ 고슬고슬.`) and the new target still carries the referenced headword `고슬고슬`. Nothing is hidden by this:
the validator, not a silent rewrite, is what surfaced the moved id.
