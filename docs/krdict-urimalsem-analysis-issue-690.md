# KRDICT · 우리말샘 원본 분석 (Issue #690)

읽기 전용 조사 보고서다. 새 사전을 canonical에 수록하거나 import 코드를 작성하지 않았고, canonical·fixture·변환기·CI·STDICT shard는 건드리지 않았다. 원본 JSON(예문·멀티미디어 포함)은 이 문서에 복사하지 않고 **집계 수치와 필드 이름만** 싼다.

- 측정일: 2026-10-15
- 기준 master: `f5b73008` (STDICT shard 64–84 병합 직후)
- 비교 기준(STDICT): `data/provenance/stdict-settlement.json`의 **허용 집합** — 427,583 entry / 499,359 sense (정책상 제외 9,004 entry / 9,784 sense). 아직 canonical에 적재되지 않은 shard가 있어도 정책 허용 집합 전체를 기준으로 삼았다.

핵심 사실 네 가지:

1. 두 사전 모두 STDICT importer를 **그대로 실행할 수 없다**. 같은 국립국어원 사전이지만 JSON 엔벌로프·필드 이름·ID 의미가 다르다 (§2).
2. **ID 충돌이 실재한다.** KRDICT entry id 53,671개 중 39,594개가 STDICT `target_code`와 숫자가 같지만 **전부 다른 단어**다. `w<id>` namespace를 공유하면 안 된다. 현 schema는 id를 `^[wr][0-9]{3,}$`로, `source`를 `["stdict"]`로 고정하고 있어 어느 쪽이든 schema 변경이 선행되어야 한다 (§4).
3. 우리말샘 1,229,530 sense 중 **444,455개(36%)는 STDICT 정책 허용 sense와 뜻풀이가 문자열 동일**하다. 이는 표기·문자열 중복 수치일 뿐이며, 우리말샘이 STDICT 수록 의미를 의미 수준에서 포함하는지는 **확인하지 못했다**(문자열이 다른 114,602 sense는 12개만 읽었다). STDICT에 없는 표기의 대부분은 분야 용어·고유명이다 (§3).
4. KRDICT 관계는 **entry 단위**(sense 번호 없음)라 대상 sense 결합이 자동으로 되지 않는다 (§2.5).

### 완결성 판단

- **KRDICT**: 내장 total이 없다. 파일명 `1..10_5000`, `11_3671`이 가리키는 합계 53,671과, 실제 고유 id를 가진 entry 수(53,671)가 정확히 일치한다. 나머지 2,884 노드는 id를 갖지 않는 관용구·속담이다(§2.2). 완결로 판단하되 **사전 공식 total과의 대조는 미확인**이다.
- **우리말샘**: 25시간(10-03 02:07 → 10-04 04:24)에 걸쳐 내려받았다. 마지막 파일명의 끝 offset은 1,229,471인데 실제 item은 1,229,530이다(+59). 사전이 다운로드 중 갱신됐다는 뜻이다. 중복 `target_code` **32개**는 모두 인접 페이지 경계에서 **내용이 동일**한 쌍이라 페이지 겹침이다. 반대로 **누락(gap)은 원천적으로 검증할 수 없다**: 페이지 오프셋 방식 다운로드는 다운로드 중 삽입·삭제가 있으면 항목이 빠질 수 있고, 사전 전체 total이 파일에 없다. 관계 대상 코드 중 약 3,100건(0.3%)은 원본 어디에도 없다 — 이것이 누락 또는 사전 쪽 삭제의 간접 증거다.
- 어느 원본도 STDICT처럼 `sha256 + 개수` 인벤토리로 봉인되어 있지 않다. import 전에 **같은 형식의 인벤토리 계약**을 먼저 만들어야 한다 (구현 아님, 권고).

`feat`의 단일값/배열 혼용과 `val` 누락은 KRDICT 파서가 방어적으로 읽어야 함을 뜻한다 (실측으로 `KeyError`를 겪었다).

### 2.2 식별자

- **KRDICT 단어 entry**: `homonym_number`·`partOfSpeech`·`vocabularyLevel`을 가진 53,671개. id는 고유하다. 단, `(표제어, homonym_number)`가 같은 쌍이 1개 있다.
- **KRDICT 관용구·속담**: 2,884 노드(관용구 2,227 · 속담 657)는 **자기 id가 없고 소속 단어 entry의 id를 그대로 쓴다**. 고유 host id는 1,160개이며 한 id에 최대 86개가 붙는다. 2,884개 모두 host id가 단어 entry에 존재한다. 따라서 **entry id만으로는 노드를 식별할 수 없고** `(id, 표제어)`가 필요하다 (이 쌍은 2,884개 모두 고유).
- **우리말샘**: `target_code`가 sense 단위로 고유(32개 겹침 제외). entry 단위 id는 없다. 동형이의어는 관계의 `word` 필드 끝 3자리 숫자(`날인001`)로만 나타나고, 본문 `word`에는 번호가 없다 (끝자리 숫자 표제어 0건).
- **STDICT 대비 충돌**: KRDICT entry id 53,671개 중 **39,594개가 STDICT `target_code` 숫자와 겹치고, 그중 같은 단어는 0개**다 (예: KRDICT `27733`=가, STDICT `27733`=공단03). 우리말샘 `target_code`와 STDICT `sense_code`·`target_code` 사이의 숫자 겹침은 측정하지 않았지만 같은 가능성을 가정하고 namespace를 분리해야 한다.

## 3. STDICT 대비 순증

표기 일치는 `convert.mjs`의 `surfaceForms` 규칙(동형이의어 번호 제거, `^`→공백, `-` 제거)과 같게 계산해 STDICT 허용 entry의 `lemma`·`search_forms`와 대조했다. **표기 일치는 같은 entry라는 뜻이 아니다.** 아래는 모두 표기 수준이고, sense 수준은 §3.3의 소표본과 문자열 일치율로만 다룬다.

| **수록 후보 (위 항목에 해당 없음)** | **898 entry · 1,009 sense** | 단어 685(명사 342 · 동사 316 · …) · 구 213 · … |

수록 후보 898개의 수준은 고급 513 · 중급 231 · 초급 23 · 없음 131이다. 예: `금전적`(관형사), `분기별`, `심화시키다`, `전화 카드`. 대부분 파생·복합어와 연어형 구다. 따라서 KRDICT의 **표제어 순증은 약 900개 수준**이고, 가치의 중심은 (a) 유의어 쌍 (b) 활용형 검색어 (c) 학습자 수준 정보이며, (c)는 Typewriter가 쓰지 않는다.

**sense 수준 (소표본)**: STDICT에 같은 표기·품사가 있고 KRDICT sense가 어떤 STDICT sense와도 문자열 동일하지 않은 60,252 sense 중 수준별 층화 12개를 읽었다. 8개는 STDICT의 기존 sense를 평이하게 바꿔 쓴 것(`잎`, `각자`, `결론`, `체온`, `촌수`, `인간사`, `운하`, `요리하다`), 4개는 판정 불가(`맑다`, `뜨겁다`, `거칠다`, `모` — STDICT 쪽 sense가 많아 확인 범위를 넘음)였다. **새 의미라고 확정된 표본은 0개**다. 이 12개로 비율을 추정하지 않는다. "새 sense 수"는 근거 없이 만들지 않는다.

### 3.2 우리말샘

1,229,530 sense를 STDICT 허용 표기와 대조:

| STDICT 표기 대비 | sense 수 | 일반어 | 방언 | 북한어 | 옛말 |
| --- | --- | --- | --- | --- | --- |
| 허용 entry에 표기 일치 | 552,286 | 527,913 | 13,021 | 10,271 | 1,081 |
| 정책상 제외 entry만 일치 | 6,771 | 5,784 | 364 | 531 | 92 |
| **표기 없음** | **670,473** | 501,842 | 96,572 | 60,458 | 11,601 |

- 표기 없음 sense가 가리키는 **고유 정규화 표기는 635,204개**(일반어 481,360 · 방언 89,805 · 북한어 55,333 · 옛말 10,945, 합집합이므로 합이 일치하지 않음).
- 표기가 일치하는 559,057 sense 중 **444,455개(79%)는 STDICT 허용 sense와 뜻풀이가 문자열 동일**하다 (태그·공백 제거 후). 이것은 표기·문자열 중복 수치이며 의미 동일성이나 의미 집합의 포함 여부를 선언하지 않는다(미확인). 뜻풀이가 다른 114,602개 중에서는 §3.3의 12개만 읽었다.
- 일반어이면서 표기가 없는 501,842 sense의 구성: **구 364,906**(분야 `cat_info` 있음 346,501), 명사 어휘 130,136(분야 있음 96,054), 동사·형용사·부사 어휘 약 3,600, 복합 품사 `관·명` 1,893, 속담·관용구 384 등. 즉 STDICT에 없는 일반어의 약 73%가 구이고, 약 69%(346,501)는 분야 표시가 붙은 용어 구다.
- 가장 위험이 낮은 조각의 크기: 일반어, 어휘 단위, `cat_info` 없음, 표기 없음 = **약 39,200 sense**(명사 34,082 · 동사 2,697 · `관·명` 1,640 · 형용사 360 · 부사 295 · 품사 없음 158). 구까지 포함하면 약 57,600. 이 조각의 품질은 **표본으로 확인하지 못했다**.

### 3.3 우리말샘 소표본 (뜻풀이가 다른 일반어, 표기가 STDICT에 있음)

대상 74,122 sense 중 분야 있음/없음 각 6개씩 12개를 읽었다.

- **분야 있음 6/6은 다른 개체의 이름이다**: `화장`=지명(경북 청송군), `연광`=중국 연호, `병원`=시 제목, `구산`=지명, `토닥-토닥`=수필집, `제어-판`=기술 용어. 동음 일반어의 새 의미가 아니라 고유명·분야 용어이므로 작가용 사전 후보로서의 가치는 소유자가 정해야 한다.
- **분야 없음 6개**: 규범 표기 안내(`들-장수`, `아이구`는 비표준 철자 → 표준어 안내, 2), 사실상 동일 sense의 품사 표기 차이(`고압-적` 명사/관형사 분리, 1), STDICT sense와 동일(`늙을로-엄`, 1), 준말·어근 안내(`월컥-하다`, `만조`, 2). **새 일반 의미 0/12.**
- 이 표본은 74,122개에 대한 추정치를 주지 않는다. 다만 "표기가 같고 뜻풀이가 다르면 새 의미"라는 가정은 **깨졌다**는 근거로는 충분하다.

### 3.5 관계 (표기쌍 기준; sense 결합 전)

※ 이 절의 표는 **관계 행(row) 수**다. 대칭 유형은 양방향으로 저장되어 고유 쌍의 약 2배이고, 출발 sense 유형도 일반어에 한정했다. 고유 쌍 기준 재집계와 연결 형태(A/B/C)별 분포는 §7에 있다.

STDICT 허용 sense의 표기쌍을 기준으로 비교했다 (STDICT 동의어 155,165쌍 · 반대말 5,734쌍 · 비슷한말 24,265쌍).

## 4. 권리·출처·비파괴 통합

`DATA-LICENSE.md`와 두 공식 정책(2026-10-15 열람)을 확인했다.

- 기본: 별도 표시가 없는 자료는 **CC BY-SA 2.0 대한민국**. 표제어·뜻풀이·품사·sense 수준 링크는 `DATA-LICENSE.md`가 이미 수록 대상으로 승인한다.
- **예외**: 이미지·동영상·음악·소리·**발음 파일**은 파일별 설정. 우리말샘은 추가로 **출전 있는 용례는 원저작권자 허락 필요**, **회원이 작성한 텍스트는 같은 라이선스로 배포하는 데 동의한 것으로 봄**을 명시한다. KRDICT 공식 정책([copyRightTermsInfo](https://krdict.korean.go.kr/kor/kboardPolicy/copyRightTermsInfo))은 별도 표시가 없는 자료에 CC BY-SA 2.0 대한민국을 기본으로 적용하고, 멀티미디어는 파일별 설정, 타인이 작성한 텍스트·멀티미디어는 저작자 허락·출처 표시를 조건으로 둔다. 예문·번역·대역어를 따로 언급하지는 않는다. 이는 **출처의 기본 규칙**이다. 이와 별개로 `DATA-LICENSE.md`는 출전 표시 예문·멀티미디어를 개별 권리 확인 전 유입하지 않는 **Typewriter 자체의 유입 경계**를 둔다. KRDICT 정책이 예문을 금지하는 것은 아니며, 예문을 제외하는 것은 후자 때문이다. 우리말샘 정책은 [copyrightPolicy](https://opendict.korean.go.kr/service/copyrightPolicy).
- 필드별 현 정책 상태는 다음과 같다. **정책이 제한하는 것**: 출전 표시 예문, 멀티미디어·발음 파일(개별 권리 확인 전 유입 금지). **정책이 수록을 허용하는 것**: 선별된 표제어·품사·뜻풀이·어휘 링크. **정책이 정하지 않은 것**: 번역·대역어(`Equivalent`, `translation_info`)와 학습자 수준 등 그 밖의 필드 — 현재 금지 규칙도 승인도 없으므로 소유자 결정 사항이다. 이 보고서는 보수적 권고로서 정하지 않은 필드를 유입 대상에 넣지 않을 것을 권하지만, 이는 기존 정책의 의무가 아니다. 또한 우리말샘의 **표제어·뜻풀이도 회원 작성분이 섞여 있음**을 알고 있어야 한다. 데이터에는 sense별 작성 주체(공식/회원) 필드가 **없다**(미확인). 이는 소유자가 라이선스 위험으로 판단할 사항이다.
- 출처 분리: 세 사전의 id를 **서로 다른 namespace**로 유지해야 한다. 현 schema는 이를 막는다: `source`는 `["stdict"]` 열거형이고, record/sense/relation id는 `^[wr][0-9]{3,}$`로 `w`+숫자만 쓴다. KRDICT id를 `w<id>`로 쓰면 STDICT와 **39,594건이 충돌**한다. 필요한 변경은 (a) `source` 열거형 확장 (b) id 접두사 분리다. 이 변경은 이번 PR 범위 밖이다.
- STDICT `record.id`·`sense.id`·shard 구성·공식 관계는 어떤 경우에도 재번호하거나 덮어쓰지 않는다. 새 출처를 (i) 독립 record (ii) 기존 sense 보강 (iii) 검색 별칭 중 어느 쪽으로 쓸지는 **소유자 결정**이다. 이 문서는 아래 §5에서 권고만 한다.
- 저자 작성 관계 백필에 미치는 영향: 새 id가 도입되면 relation backfill 인벤토리·source-bound 검증이 새 namespace를 알아야 한다(현 검증은 `w`/`r` id 전제).

실측 근거: `convert.mjs`/`inventory`에 우리말샘·KRDICT 원본을 넣어 실행.

최소 구현 변경안(분석만): (1) schema `source` 열거형 확장과 id 접두사 분리 (2) 사전별 source 인벤토리 계약 (3) LMF/우리말샘 → STDICT 중간 형태 변환 adapter (4) 사전별 `classifySense` 정책 모듈. `build-shard`·validator·SQLite는 그대로 둔다. 새 통합 파이프라인은 만들지 않는다.

## 6. 권고 (분석 시점의 권고, 이력)

이 절은 소유자 결정 이전의 분석 시점 권고를 이력으로 보존한다. **최종 판정은 §7.0의 KRDICT HOLD, 우리말샘 신규 표제어 전량 수록 HOLD, 관계어 활용 전략 채택·구현 HOLD**이며 이 절의 KRDICT 권고와 질문은 그 판정을 바꾸지 않는다.

### KRDICT — **HOLD** (분석 시점 권고는 "GO (좁은 범위)"였으며 소유자가 채택하지 않았다)

아래는 조사 결과로 보존하는 분석 시점 권고다. 이번 단계에서는 도입하지 않고 adapter도 착수하지 않는다.

- 우선순위: 신규 표제어 898 entry(§3.1) → 이후 정책 판정이 필요한 `품사 없음`·`문법‧표현`.
- 대상 필드(권고): 현 정책이 수록을 허용하는 표제어·품사·뜻풀이. 출전 예문·멀티미디어·발음은 정책상 제한된다. 대역어·학습자 수준은 정책이 정하지 않은 필드이므로 보수적으로 제외를 권하며, 포함 여부는 소유자 결정이다.
- 관계: **HOLD**. 유의어 3,181쌍·반대말 487쌍이 순증이지만 대상이 entry 단위이고 다의어 대상이 약 40%다. 단일 sense 대상(9,276건)에 한정한 별도 결정이 필요하다.
- 검색 별칭(활용형): 순증 이익이 미측정이라 HOLD.
- 이유: 규모가 작고(약 900) 위험이 낮으며, adapter 하나로 STDICT 변환 경로 전체를 재사용할 수 있다. 다만 id 충돌과 schema 변경은 선행 조건이다.

### 우리말샘 — 신규 표제어 전량 수록 **HOLD**, 관계어 활용 조사는 **GO (§7)**

- 순증의 대부분이 분야 용어 구, 고유명, 방언·북한어·옛말이다. "작가용 사전"에 맞는 선택·UI 정책 없이 전량 수록을 전제하지 않는다.
- 소유자 결정이 끝나기 전에는 어떤 import도 하지 않는다. 결정 후 가장 낮은 위험 조각은 §3.2의 약 39,200 sense이지만 그 품질은 미확인이므로 **먼저 표본 품질 확인**이 필요하다.
- 관계 코퍼스는 STDICT 정확도 계약과 다르므로 기계적으로 `direct`나 `near`로 넣지 않는다. 소유자 결정(우리말샘은 기존 표제어의 관계어 확장에 쓴다)에 따른 관계 연결성 조사는 §7에 있다.

### 소유자 결정 사항 (분석 시점; KRDICT 관련 2·3번은 §7.0 HOLD로 이번 단계에서 다루지 않음)

1. 새 출처 id namespace와 schema 변경(`source` 열거형, id 접두사)을 허용하는가?
2. 번역·대역어·학습자 수준 등 정책이 정하지 않은 필드를 수록 대상에 넣는가? KRDICT: 898개 후보를 독립 record로 수록하는가, `문법‧표현`(어미형)을 어떻게 다루는가?
3. KRDICT 관계를 entry→sense 결합 규칙과 함께 받아들이는가, 단일 sense 대상으로 한정하는가?
4. 우리말샘: 방언·북한어·옛말·분야 용어·고유명의 수록 범위와 UI 분리 정책.
5. 우리말샘 회원 작성분을 허용하는 라이선스 위험 판단, 정확도 계약(비슷한말)의 사용 방식.
6. 세 사전이 같은 표기를 가질 때: 독립 record / 기존 sense 보강 / 검색 별칭 중 무엇인가?

### 7.1 용어와 집계 기준

- **관계 행(row)**: 원본 `relation_info` 항목 하나. `비슷한말`·`참고 어휘`·`반대말`은 양방향으로 저장되는 경우가 많아 행 수는 고유 쌍의 약 2배다. 행 수와 고유 쌍을 섞어 비교하지 않는다. §3.5의 숫자는 행 기준이며, 이 절은 고유 쌍을 병기한다.
- **고유 표기쌍 / 고유 sense쌍**: 정규화 표기(§3 규칙) 또는 `target_code`의 쌍. 대칭 유형(`비슷한말`·`참고 어휘`·`반대말`)은 순서 없는 쌍, 비대칭 유형은 순서 있는 쌍으로 센다.
- **연결 형태**: 관계 양끝 sense의 **표제어 표기**가 STDICT 허용 표제어에 있는가로 분류한다.
  - (A) STDICT ↔ STDICT: 양끝 표기가 모두 STDICT 허용 표제어
  - (B) STDICT ↔ 우리말샘 전용: 한쪽만 STDICT 허용 표제어
  - (C) 우리말샘 전용 ↔ 우리말샘 전용: 양끝 모두 STDICT에 없는 표기
- **표기 일치 ≠ sense 연결.** 같은 표기의 STDICT sense가 어느 것인지는 별도 문제다. 확정할 수 있는 하한으로 **뜻풀이 문자열이 STDICT 허용 sense와 동일한 우리말샘 sense**를 "sense 결합됨"으로 센다(태그·공백 제거 후 비교, 의미 판정 아님). 결합됨이 아닌 것은 "불일치"가 아니라 **미확인**이다. 아래 sense 결합 건수는 이 하한이고 확정치가 아니다.
- "새 쌍"은 해당 표기쌍이 STDICT 허용 sense의 `동의어`·`비슷한말` 쌍 집합(양방향)에 없는 것이다.

- 기존 어휘망을 실제로 늘릴 수 있는 규모는 **(B)** 새 표기쌍 30,749, sense쌍 34,367이다. (A)의 새 쌍 62,223은 양끝이 이미 STDICT 표제어이므로 표제어를 늘리지 않고 관계만 늘린다. (C)는 양끝이 STDICT에 없어 기본 어휘망과 연결되지 않는다.
- 그러나 (B)의 우리말샘 전용 쪽(68,347행)은 **대부분 분야 용어**다: 일반어·분야 표시 있음 어휘 31,289 + 구 28,614 = **59,903행(88%)**. 분야 표시가 없는 일반어는 어휘 3,553 + 구 1,800 = 5,353행(8%)이고, 방언 2,516, 북한어 549, 옛말 14, 기타 12이다. 즉 (B)가 어휘망을 크게 키울 수 있다는 기대는 **전문어를 수록할 때만** 성립한다.
- (A) 새 sense쌍 64,379 중 51,879(81%)는 양끝이 STDICT 허용 sense와 **뜻풀이 문자열 기준으로 대응**한다(의미 동일성 판정이 아니다). (B) sense쌍 34,367 중 STDICT 쪽이 뜻풀이 문자열 기준으로 대응하는 것은 18,589(54%; 새 쌍 18,588 + 기존 쌍 1)이고 15,778은 미확인이다. 미확인은 다의어 표기에서 연결이 불확실하다는 뜻이다.
- 위 수치는 **유형이 `비슷한말`인 관계**일 뿐이며, STDICT `동의어`(정확도 계약이 확인된 import 대상)와 같은 정확도를 가진다는 근거는 없다.

- `옛말` 관계도 같은 구조다: 출발은 일반어 sense(17,067행), 대상은 옛말 sense. 옛말 sense 12,774개 중 **8,445개(66%)**만 들어오는 관계가 있고 뜻풀이가 `‘…’의 옛말` 형태인 것은 8,576개(67%)다. 즉 옛말→현대어 연결 정보가 **필드로 있는 비율은 전체의 약 3분의 2**다. 옛말 표제어 12,774개 중 **5,948개(47%)**가 현대 한글 음절 이외의 문자(옛 한글 조합·사용자 정의 문자 등)를 포함해, 표시·검색 정규화 문제가 있을 수 있다(미검증).

표본에서 읽은 **분류 규칙 판단 근거** (일괄 매핑하지 않는다):

- `비슷한말`: 일반 어휘의 같은 의미축 이칭(도월/계양)과 **전문어 변이**(회로-계/멀티미터)가 섞여 있다. 양끝 sense가 결합되고 의미축이 같은 경우에 한해 `direct` 후보, 전문어 변이와 어감 차이는 별도 표시이거나 `near`·연상 후보다. 유형 이름만으로 `near`나 `direct`를 정하지 않는다.
- `방언`: 방언형 + **지역** + 표준어 sense를 가리키는 정보다. 현 relation type 8종 어디에도 들어맞지 않는 **별도 속성**이 자연스럽다(`direct`·`near` 아님).
- `옛말`: 옛말형 + 현대어 sense. 위와 같은 별도 속성이며 옛 한글 표시 문제가 있다.
- `참고 어휘`: 모음 교체형, 의학 연관어 등 **관련어 성격이 다양**하다. `near`·`association` 후보이거나 제외.
- `상위어`·`하위어`: 상하·부분 관계. `association` 후보이거나 현 type에 없는 상하 관계. `direct`는 아니다.
- `반대말`: `antonym` 후보이나 접두 부정형은 어휘적 반의어인지 판단이 필요하다.

### 7.5 STDICT에 없는 관계 대상 표현의 최소 수록 형태 (분석만)

현재 코드 계약으로는 **STDICT에 없는 표현을 관계 대상으로만 두는 형태가 없다.**

- schema: 관계(`relation`)는 `target`(`^[wr][0-9]{3,}$`)과 선택적 `target_sense`를 가지며, 출발 sense의 `relations` 배열 안에 저장된다. 관계 대상은 **완전한 record**여야 한다: `senses` 최소 1개, `pos`(열거형)와 비어 있지 않은 `gloss`, `search_forms` 최소 1개, `source`(`["stdict"]`).
- SQLite: `relations.target_record_id`는 `records(id)`에, `(target_sense_id, target_record_id)`는 `senses`에 외래 키로 묶인다. `type`은 8종 CHECK, `note`는 NOT NULL이다.
- 검색: 유효한 in-scope record는 **모두 직접 검색 대상**이다(`docs/editorial-model.md`: `start`와 `reference-only` 모두 직접 검색 가능). role은 검색 범위를 제어하지 않는다. 따라서 우리말샘 전용 표현을 record로 만들면 **일반 검색 항목이 된다.**
- `r` 접두사(`pure reference-only`, `candidate_id` 금지)는 스키마·검증기에 이미 있으나 **현재 canonical에는 `r` record가 없다**(측정). 이 namespace는 `w`(STDICT) id와 충돌하지 않는다.

필요한 최소 변경 방향(구현하지 않음, 소유자 결정):

1. **보조 어휘 노드의 검색 노출 속성**: 직접 검색에 나오지 않고 관계 대상으로만 나오게 하는 필드(또는 role 값). schema, `lexical-quality`·`dataset-integrity` 검증, SQLite 스키마, 런타임 계약과 검색 필터, UI 경로에 모두 영향이 있다.
2. **출처·id 보존**: `source` 열거형에 우리말샘 추가, 노드 id를 `w`와 겹치지 않는 namespace로(`r` 재사용 가능), 원본 `target_code`와의 대응을 provenance로 보존. 세 사전 id를 서로 다른 namespace로 유지한다.
3. **sense 대응**: 관계는 **출발 sense의 `relations`**에 저장되므로, STDICT sense에서 우리말샘 전용 노드로 가는 관계는 **기존 STDICT sense 레코드(shard)를 갱신**해야 한다. STDICT `record.id`·`sense.id`·shard 구성·공식 관계를 재번호·덮어쓰기하지 않는 원칙과 이것이 양립하는 방식(관계 추가만 허용인지, 별도 파일인지)은 소유자 결정이다. 출발 sense는 §7.1의 뜻풀이 문자열 기준 대응 하한(`방언` 91%, `옛말` 90%, `비슷한말` (B) 54%)에서만 정해지고 나머지는 미결합 상태로 남으며, 이 대응은 의미 동일성 판정이 아니다.
4. **관계 type**: `방언`·`옛말`은 현 8종에 없다. 새 type 또는 별도 필드는 소유자 결정이다. `비슷한말`·`참고 어휘`·`상위어`·`하위어`도 위 §7.4의 근거 없이 `direct`/`near`로 기계 대응하지 않는다.
5. 관계의 `note`(필수)에는 원 관계 유형과 출처를 남긴다.

KRDICT에만 있는 큰말·작은말·센말·여린말·본말·준말·높임말·낮춤말은 이 우리말샘 분석에 섞지 않았고 향후 별도 선택지로 남긴다.

### 7.6 이 절의 한계

- 연결 형태 분류는 **표제어 표기** 기준이다. sense 결합은 뜻풀이 문자열 일치의 하한이며 의미 동일성 판정이 아니다.
- 실물 점검은 분류 규칙의 근거일 뿐 정확도 추정이 아니다. 특히 `비슷한말`의 정확도 계약은 미확인이다.
- 옛말 표제어의 비표준 문자 비율은 문자 범위로만 계산했고 실제 렌더링은 검증하지 않았다.
- 우리말샘의 누락(공식 total 부재)은 §1 그대로이며, 관계 대상 누락은 위 표의 "대상 누락"만 측정했다.

## 8. 재현 방법

모든 집계는 Git 밖(`~/.cache/typewriter/reference/dict/{stdict,krdict,urimalsem}`)의 원본을 읽기 전용으로 읽고, 중간 산출물은 세션 scratchpad에만 두었다. 리포지토리에는 코드를 추가하지 않았다. 같은 수치를 다시 얻는 절차:

1. **STDICT 기준 집합**: 레포의 `flattenSenses`·`classifySense`·`surfaceForms`·`cleanDefinition`을 임시 스크립트에서 import해 88개 파일을 읽고 entry별 `{word, unit, 표기형, sense별 {pos, include, 정리된 뜻풀이, lexical_info}}`를 한 JSON으로 덤프한다. 합계가 `436,587 / 509,143`이고 허용 집합이 `427,583 / 499,359`이면 정책과 일치한다 (`data/provenance/stdict-settlement.json`).
2. **KRDICT**: 11개 파일에서 `LexicalResource.Lexicon.LexicalEntry`를 읽는다 (`feat`는 객체/배열을 모두 배열로 정규화, `val` 누락 허용). 센 것: 노드 56,555, `homonym_number` 보유 53,671, 보유하지 않는 관용구·속담 2,884, id 중복 1,160, sense 76,833, `SenseRelation` 32,791.
3. **우리말샘**: 25개 파일의 `channel.item`을 읽는다. 센 것: item 1,229,530, 고유 `target_code` 1,229,498(중복 32, 모두 동일 내용·인접 페이지), `word_unit`/`pos`/`senseinfo.type` 분포, `relation_info` 유형·결합.
4. **표기 대조**: 위 §3 규칙(`surfaceForms` 이식)으로 정규화한 표기를 STDICT 허용/제외 집합과 비교한다. 뜻풀이 문자열 일치는 태그·공백 제거 후 비교이며 의미 동일성이 아니다.
5. **관계 대조**: 출발 표기와 대상 표기(동형이의어 숫자 제거)의 쌍으로 STDICT `동의어`/`반대말`/`비슷한말` 쌍 집합과 비교한다.
6. **소표본**: 시드 `20261015`로 §3.1은 수준별 4개씩, §3.3은 분야 유무별 6개씩 추출해 사람이 읽는다.

STDICT 쪽 수치는 `node scripts/stdict/inventory.mjs --verify`와 `settle.mjs`가 이미 재현한다.
