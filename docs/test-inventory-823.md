# Issue #823 Test Inventory and Measurement

## Scope and counting rule

The audit baseline is the exact #825 merge commit `6b83ccae995d55f3d85043fdc3d3445ab244811b`, which is the base of this issue branch after the requested rebase. The table audits each conventional test module tracked at that baseline (`*.test.mjs`, `*.test.js`, and Python `test_*.py`) and records its representative asserted contract or failure condition, disposition, current caller, and route. Current test modules are found in the CI registry or the explicit Vitest list; the registry regression checks that every Node test module has exactly one automatic owner and no retired manual test remains.

The two browser scripts are not conventional test modules: `scripts/test-web-landing-integration.mjs` and `scripts/test-web-runtime-integration.mjs` remain explicit manual product checks. CFT commands remain in the package scripts for current MV3 runtime and package contracts. Vitest watch mode is an editor loop, not a test route.

## Current route and overlap decisions

- **KEEP / Normal always:** source JSONL/schema/integrity checks, Canonical context and record-to-Meaning model, relation source provenance and rank agreement, SQLite build and Full-to-Lite projection, build provenance, product query/runtime, package, artifact, CI-runner, and CI-registry contracts. Vitest has an explicit 12-file list in `scripts/ci/product-unit-test-files.mjs`; Node test modules each have one registry owner.
- **KEEP / affected Deep:** the four relation backfill/apply/correction Node tests share the registered relation contract when those dependencies change; artifact policy is selected for its exact dependencies. `ci:all` includes current Deep checks. Manual product checks are called explicitly for changed browser/package surfaces.
- **CONSOLIDATE:** `global-canonical-audit` checks the complete current Canonical data and source rules in the shared context; Normal `m2-audit` builds/validates the current-revision Full SQLite once and checks the Canonical-to-Full projection. They share the one context/build and are distinct source-data vs generated-database contracts. Deep `deep-m2-reproducibility` independently rebuilds current Canonical Full and Lite to verify reproducibility. The removed `tests/m2-pipeline.test.mjs` synthetic integration and `tests/reproducibility.test.mjs` fixture builds duplicated this integrated path; their still-current provenance assertions moved to Normal `tests/build-provenance.test.mjs`.
- **DELETE:** retired Factory candidate production, batch handoff, corpus/literature ingestion, local morphology/cache, Meaning-editing, migration, synthetic scale, and obsolete CI tier tests. Current source and relation checks remain where their functions still have callers (for example, relation source-authority modules and sharded writes). The #827 `tests/definition-numbering.test.js` was deleted as the issue requests; it only checked rendered numbering markup and CSS selectors.

## Test enrollment rule

A Node test module must appear exactly once in a current CI check's `testFiles` or explicit `node --test` arguments. Vitest files are maintained in `scripts/ci/product-unit-test-files.mjs` and the same list is applied by `vitest.config.js`; they run through the Normal product check. Do not register retired scripts as Manual. Add a manual route only for an explicit current product boundary, such as the browser and packaged MV3 commands. A shared defect needs a generalized regression at its current producer, validator, builder, or consumer, not a one-word or historical-batch test.
