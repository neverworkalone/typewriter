# D1 Skip-Sense whole Drop — focused PR technical review

Read this PR HEAD's root `REVIEW.md` first. This card is for `[D1/<model>] <SSS>` data PRs under standing production issue #10171. It is PR review Stage 1 (technical `+1`/`-1`), not the final Stage 2 exact-HEAD CI/merge gate. **D1 review is a light technical review centred on the deletion verification (#10274); it does not re-review the category judgments.** The Stage 1 `+1` and the Stage 2 same-HEAD `+1`/CI/merge contract are unchanged.

D1 deletes, in both directions, every Typewriter-authored Relation directly connected to a confirmed `d:"s"` Sense (#10174) that the D1 author model judged to clearly fit one of the #10171 §3.2 whole-Drop categories. It is Relation-only: Relation files of other owning shards may change; Canonical, Candidate, Drop and selection files do not. The verification and reporting contract is in `docs/relation-factory.md` §4-F.

## When this card applies

- Title `[D1/<model>] SSS`, body `Refs #10171`, **and** the actual merge-base → PR HEAD change is only `data/relations/relation-*.jsonl`.
- A PR that also changes code, prompts, cards, category criteria or any other path goes through `code.md` as a normal review, even with a D1 title. A title or a `no-review` label alone never routes a PR here. A D1 production data PR itself is **not** `no-review`.

## Responsibility boundary

| Responsibility | Owner |
| --- | --- |
| P/S/E selection | Confirmed #10174 result; never re-selected |
| Limiting D1 input to exact `s` Senses | Common input code; not re-checked by the model per PR |

## Stage 1 review scope

1. **Changed paths:** the actual change is limited to `data/relations/relation-*.jsonl`.
2. **Deletion verification:** a valid passing D1 verify result exists for this exact HEAD (no missed deletion of an authored Relation of a D Sense; no unrelated row deleted, added or modified; only allowed Relation paths). Reuse the existing result; do not re-run verify when a valid result exists. Run the official D1 verify once only when no result for this HEAD can be found; a missing PR-body summary alone is not a `-1` (`REVIEW.md` §5).
3. **Open blockers:** every unresolved earlier blocker on this PR.
4. **Concrete defects already raised or found:** only those, within their stated scope.

Do not read every deleted Relation, every D judgment, every non-target/hold Sense or the full Relation diff. Do not generate the full `decisions` listing for review; query only the named Senses of a concrete doubt.

## `-1` grounds

Only an actually confirmed problem:

- deletion verification failed or is incomplete for this HEAD;
- an allowed-path or editing-scope violation;
- concrete evidence that a refusal, error or unprocessed Sense was recorded as a normal D judgment or a normal completion;
- an **already-found clear category misapplication**: name the exact Sense, its gloss and the explicit category condition it contradicts.

Not grounds and not mandatory procedure: per-PR full semantic review, mandatory sampling or initial audit; re-reading all D/non-target judgments; "this could be useful to a writer" or "this Relation could be kept"; a high or low deletion count or ratio; asking another model to approve the same subjective judgment. A Relation of a D Sense is not kept because its other endpoint is `p` or a non-target.

## Fixing, re-review and roles

- A confirmed problem is handled through the existing amend/FIXING path: look up only that Sense's gloss, category and judgment and correct that judgment. Keep the deletion effect of other D endpoints and concurrent edits under the common relation-key contract. A fix run does not re-judge every Sense or draw samples.
- A recurring real error is fixed in a separate common prompt/rule/code change, not by adding a review step to every production PR.
- If amend/replay creates a new HEAD whose content changed, the deletion verification is redone on the existing path, and re-review checks only that result, the earlier findings, the author's replies and the changed delta. A completed batch is not reopened for later normal edits.
- Record a substantiated `+1` when no confirmed blocker remains, also on an unchanged HEAD after a valid rebuttal. Never a `+1` without evidence. Do not query or wait for CI, and never merge.
- Final Stage 2 checks the valid same-HEAD `+1`, no unresolved blocker and the required exact-HEAD CI, then merges at the expected HEAD. It does no semantic or technical re-review.

**Residual risk:** a Sense outside the categories wrongly judged D is not caught by verify or build. The author reduces it by choosing D only for clear cases; review does not repeat that judgment per PR.
