# S2 Relation Admission Part — focused PR technical review

## Scope

Applies only to S2 Relation/Drop data-only Part PRs. Read the PR HEAD's root `REVIEW.md`; mixed implementation/data PRs use `code.md`. Editorial policy: `docs/relation-editorial-policy.md`; production contract: #927. Do not routinely reread #927.

## Relation-first review priorities

- **Admission before Type/Tier:** prioritize newly admitted Relations. Confirm each inspected path's exact source Sense, independent writer-facing expression/scene/image value, suitable Type/Tier against same-source peers, and exact target Sense or justified text-only choice. A low Tier cannot make an editorially valueless approval acceptable.
- **Same-Sense peer redundancy (all technical reviewers):** For inspected newly approved Relations, compare the target expressions **with one another**, as well as with available approved peers of the same source Sense, not only with the source lemma. Separate Relation rows that merely repeat one writer-facing choice through noun/verb ending changes, trivial derivation or spacing variation should have been `D e` rather than another approval. Keep genuinely distinct meaning, grammatical use, register or imagery; shared root/spelling alone never proves redundancy. Multiple forms within **one ID Relation row** are aliases, not separate redundant Relations. Check suspicious `e` Drops for the opposite error: loss of a useful expression. Apply this within existing source-Sense risk sampling, not a whole-Part or historical peer sweep.
- **Drops after Relations:** risk-review suspicious `x` Drops (connected paths incorrectly called unrelated/wrong Sense) and `e` Drops (useful, independent expressions or scenes excluded). Preserve plausible unusual or indirect writer-facing paths. Do not exhaustively inspect every Relation or Drop.
- **Risk-based grouping:** review Relation and Drop risks by source Sense and peers; expand only on specific evidence of a broader defect. No fixed semantic sample size, Drop percentage, Tier quota, whole-Part re-edit or repeated Stage 1 candidate-form screening. Judge any leaked trivial candidate under S2 admission rules.
- **Blocking threshold:** require concrete source-Sense/peer evidence for a blocker. Minor or subjective Tier differences are non-blocking; block only evidenced, material rank inversions against same-source peers. Confirmed material admission, Sense-binding or Type errors remain blockers.

## Validation and special cases

- Reuse reliable successful official Part `verify --shard SSS --batch BB --part PP` evidence, or run the official verifier only to resolve a concrete gap. Its full structural/accounting checks still cover all Relation/Drop rows regardless of semantic review scope. Do not require unfinished sibling Parts or Batch/shard completion to pass a single Part review.
- S2 editorial Drops: `x` = unrelated/wrong Sense; `e` = connected but without independent writer value. `z` is Stage 3-only; `f` is Supervisor-only. Apply existing code-specific validation, including the `x`-only gloss-name check.
- If `f` rows exist, verify each one's source-bound single-candidate failure, one correction attempt and official save-chunk failure evidence; report their count separately from editorial `x/e` Drops.
- Authored ID links mirror source `tp`/`rv` in both directions (#2446). Equal reverse values are required, not a defect; mismatched persisted values are a blocker. Text-only links have no reverse.
