# 문학 TXT 로컬 DB 파일럿 보고 (#332)

원문·발췌·SQLite 산출물은 Git에 포함하지 않는다. 이 문서는 텍스트 없는 수치와 파일 경로 메타데이터만 담는다. 이용 범위는 [외부 자료 검토](external-material-review-public-domain-literature.md)를 따른다(제공 기관 공유마당, 소유자 진술 기반, 동봉 일람 기준 이용조건 '만료', 재배포 미승인).

## 도구와 계약

- `scripts/reference/literature-index.mjs` (+ `build-literature-index.mjs` `select|build|verify`, `search-literature-index.mjs`). `npm run reference:literature:{select,build,verify,search}`.
- 출력: `data/reference/indexes/literature-pilot-2026.sqlite`(Git 제외). `written-corpus-2025.sqlite`와 NIKL 파서는 건드리지 않는다.
- 스키마(v1): `source_files`(상대경로, SHA-256, bytes, 인코딩, BOM, 개행 규약, 말미 개행, NFC 여부, 상태/경고), `works`(장르, 파일명 유래·**미검증** 저자/제목, 제목이 첫 텍스트 행에 나오는지 여부, 출처/퍼블릭도메인 근거), `text_units`, 외부 콘텐츠 FTS5 trigram `unit_fts`, `index_metadata`(스키마/빌더 버전, 입력 매니페스트 digest, 개수, 정렬된 논리 행 digest, 도구 식별자).
- 충실(faithful) 계층: `text_units`는 물리적 한 줄 = 한 단위이며 행별 종결자(`\r\n`/`\n`/`\r`/없음)를 그대로 저장한다. 의미 문단은 만들지 않는다. `block_ordinal`은 빈 줄로 구분되는 연(stanza)/덩어리 번호일 뿐이다. UTF-8 BOM만 `source_files.has_bom`으로 분리 기록한다. 정규화(NFC 포함), 철자·문장부호 변경은 없다. 파생 검색 계층은 **없음**(FTS5 trigram이 충실 텍스트를 직접 색인하고, 결과는 `instr()`로 재검증).
- 빌드: 명시적 경로 목록(매니페스트)만 처리, 파일 하나라도 오류면 기존 DB를 건드리지 않고 중단, 임시 디렉터리에서 quick_check/foreign_key_check/FTS integrity-check 후 원자적 `rename`. 모든 작품을 DB 단위에서 재구성해 디코드된 TXT와 정확히 비교한 뒤에만 완료한다.
- 검색: 1–2자 literal scan, 3자 이상 FTS5+`instr`. 한도 1–200, 정렬은 장르(poem→novel→essay)·상대경로·행 번호. 결과는 literal 문자열 일치 증거이며 표제어/품사/단어 빈도가 아니다.

## 표본 추출

전수 인벤토리(TXT 12,352개: poem 8,349 / novel 1,140 / essay 2,863; 총 90.4MB)를 상대경로 순으로 수행했고, 장르별 5개씩 **15편**을 결정적 규칙(중앙값 크기·다단락, p95 크기, 첫 CP949, 첫 BOM, 첫 NFC 아님, 첫 말미 개행 없음)으로 골랐다. 선정 목록은 로컬 매니페스트(`literature-pilot-2026.manifest.json`, Git 제외)에 `selection_rule`과 함께 있다. 장르별 선정 수: poem 5 / novel 5 / essay 5. 로컬에서 이용할 수 없던 장르는 없었다. LF-only 파일은 극소수라 표본 규칙 상한(장르당 5편) 때문에 선정되지 않아 표본의 개행은 CRLF뿐이며, LF-only 처리는 합성 테스트로만 검증했다.

## 전수 인벤토리 결과(수집 전체, 본문 비저장)

| 장르 | ok | warning | error |
|---|---:|---:|---:|
| poem | 3,680 | 3,042 | 1,627 |
| novel | 418 | 639 | 83 |
| essay | 1,224 | 1,474 | 165 |

- 인코딩: UTF-8 10,467(그중 BOM 67), CP949 10(poem 3·novel 5·essay 2). 모두 명시 오류 아니면 성공/경고로 보고하며 빈 값·깨짐은 성공이 아니다.
- **오류 원인**: 빈 파일 758(전부 poem), 사설 영역(PUA) 코드포인트 1,107(poem 864·novel 80·essay 163; 전부 유효한 UTF-8이며 폰트 의존 미매핑 글리프 대용으로 보임 → 충실하게 해석 불가라 fail-closed), 바이트 해독 불가 9, U+FFFD 포함 1.
- **경고**: NFC 아님 4,665(표본 NFC 아님 파일 9편은 모두 CJK 호환 한자 U+F9xx가 원인, 예: 金 U+F90B ≠ U+91D1; 전수 원인 분포는 미조사), 선행 빈 줄 893, 말미 개행 없음 110, UTF-8 BOM 67, CP949 10.
- 개행: 거의 전부 CRLF(LF-only는 극소수, 정확한 수는 미집계).

## 표본 15편: 구조/충실도 관찰

- 15/15 성공(경고 포함), 합계 5,359 단위, 원문 271,809 bytes. DB에서 재구성한 텍스트가 15편 모두 디코드된 TXT와 정확히 일치했고(`verify`), UTF-8 BOM·CRLF·말미 개행 없음·NFC 아님·혼합 한자 포함.
- **poem**: 행=시행, 빈 줄=연 구분. 시행 길이 중앙값 10–31자, 문장 종결 부호 없음에 가까움. 시행·연 단위가 구조를 그대로 보존.
- **novel**: 본문이 약 40자에서 **하드랩**되어 있고, 문단은 들여쓰기 시작 줄과 빈 줄로 표시된다(표본 일부는 빈 줄 없이 들여쓰기만, 이효석 표본은 거의 모든 줄 사이에 빈 줄). 따라서 물리 행은 문단이 아니며 행 경계를 넘는 어구는 literal 검색에 잡히지 않는다. 들여쓰기 문단 복원은 가역적 파생 규칙으로 별도 정의가 필요하다. 대사 부호(따옴표)는 변경 없이 보존.
- **essay**: 제목·저자·빈 줄·본문 순서의 같은 하드랩 구조, 한자 병기 행이 많음(표본에서 최대 360/404행). 각주는 본문 행으로 그대로 남는다.
- **제목 검증**: 파일명 제목이 첫 텍스트 행에 나타난 작품만 `title_in_first_unit=1`. 메타데이터는 전부 `filename (unverified)`.

## 검증 매트릭스(합성 fixture, 12개 테스트)

가역 분할(CRLF/LF/CR/혼합/말미 개행 없음/유니코드 공백), UTF-8·BOM·CP949 판별과 빈/BOM만/UTF-16 BOM/잘린 바이트/NUL/U+FFFD/PUA/ CP949+BOM 거부, 경로가 포함된 fail-closed 오류와 직전 DB 보존, 중복 제목/파일명 구분, 입력 변경·삭제 시 digest/검증 변화와 재빌드 동일 논리 digest, SQLite integrity/FK/FTS, 1–2자·한자·한도·결정적 정렬 검색, 권한 게이트, CLI.

## 측정 및 외삽(불확실성 큼)

| 항목 | 값 |
|---|---|
| 표본 15편 빌드 | 0.11s, DB 1.37MB / 원문 0.27MB = 5.0배, 피크 RSS 약 79MB |
| 105편 층화 표본(전체 1/100, 임시 DB) | 0.26s, 0.77MB → 3.5MB = 4.5배, 피크 RSS 약 165MB(인벤토리 포함) |
| 전수 인벤토리·디코드 | 3.2s, 피크 RSS 167MB |

외삽: 처리 가능 원문 약 73MB × (3.5–5배) ≈ **0.25–0.4GB** DB, 빌드 수십 초 규모 예상. 다만 표본이 작고 하드랩/한자 비중이 다른 대형 작품에 따라 편차가 있어 ±2배 불확실성으로 본다. 현재 빌더는 전체 분석을 메모리에 모으므로 전수 처리는 작품별 스트리밍 삽입이 필요하다.

## 다음 전수 TXT 색인 이슈 권고

1. PUA 1,107개, 빈 poem 758개, 해독 불가·U+FFFD 10개의 처리 방침(제외 보고 vs 문자별 대응표). 본 파일럿은 명시 오류로 거부한다.
2. 하드랩 소설/수필의 **가역적 문단 단위**(들여쓰기·빈 줄 규칙) 파생 계층과 행 경계 넘는 검색.
3. 파생 NFC/호환 한자 검색 계층(충실 계층과 분리·digest 별도). 현재는 호환 한자로 저장된 金 등을 통일 한자 질의로 찾지 못한다.
4. 작품 단위 스트리밍 빌드와 메타데이터 검증(제공 기관 메타데이터는 별도 승인·검토 후).
5. 동봉 일람(xls: 작품명·저작자·주제분류 포함)을 별도 검토 후 파일명 유래 메타데이터 검증 소스로 쓸지 결정. 본 파일럿은 xls를 파싱하지 않는다.

## TXT 원본 보존 결정

원본 TXT는 삭제·재작성하지 않는다. DB는 디코드된 텍스트를 정확히 복원하지만 CP949 원본의 바이트 수준 복원(재인코딩), PUA·미검증 파일, 원본 SHA-256 대응은 증명되지 않았으므로 삭제 결정은 별도 소유자 확인과 전수 검증 이후로 미룬다.
