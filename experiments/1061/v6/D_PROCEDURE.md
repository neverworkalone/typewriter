# D 생성 절차 V6 — 문맥 확장 · 발굴/검증 분리 · 전량 재검증

이 문서는 특정 배치에 종속되지 않는 **D(말뭉치 문맥) 방식 범용 절차**다. 단어별 예외나 고정 후보 할당량을 두지 않는다. V5(`../v5/D_PROCEDURE.md`)의 문제를 바로잡고, A/B나 다른 생산자의 결과를 참조하지 않는 독립 실행을 전제로 한다.

## 0. V5에서 확인된 문제와 V6의 대응

| V5 문제 | V6 대응 |
| --- | --- |
| 초기 4문맥에서 발굴을 끝냄 | 4→8→12→16 창 확장을 조건과 함께 강제 |
| `inspected_8_windows`를 종료 사유로 사용 | 창 개수는 종료 사유가 아니다. `no_more_distinct_contexts` / `no_new_relation_after_N` / `inspected_16`만 사용 |
| `verified_context_count`가 판독 예산으로 보고됨 | 실제 sense-bound `VERIFIED` 수를 `inspected`(판독)와 분리 계측 |
| 기존 후보가 자동 생존 | 기존 후보도 동일 기준으로 `KEEP/REWORK/DROP/UNCERTAIN` 재판정 |
| 자체 필터가 공출현·오독을 통과시킴 | 형태 경계 검사 + 대립 편집(PASS D) + 재발굴(PASS E) |
| 표제어 포함 후보를 기계적으로 처리 | 표제어 exact 일치만 제외하고, 포함 후보는 독립 관계 기여 여부로 판정(자동 삭제 아님) |

## 1. 입력과 경계

- Canonical 배치: `data/canonical/stdict-<SSS>.jsonl`의 정확한 500행(마지막 배치는 83행)과 그 모든 sense를 고정한다.
- D 문맥 자료: 승인된 로컬 문어 말뭉치 SQLite(읽기 전용), bigram postings sidecar, FTS trigram. 경로·스키마는 저장소 문서의 현재 계약을 따른다.
- 문맥 원문·검색 로그·로컬 감사 기록은 Git/PR에 넣지 않는다. Candidate JSONL만 제출한다.
- 다른 방식(A/B/C)이나 다른 모델의 후보·비교 결과를 읽지 않는다.

## 2. PASS A — Search / Sense Verification

1. 배치의 모든 record·sense를 `sense_id/lemma/pos/gloss`와 함께 고정한다.
2. 검색 표면형을 만든다: 표제어, `search_forms`, 어간, 활용형(하다→하/해/했/한/할/합, 되다→되/돼/된/될/됩). 표제어를 그대로 코퍼스에 요구하지 않는다.
3. 정확한 sense-bound 문맥을 최대 16개 확보한다. 같은 문서는 최대 2문맥이다.
4. 각 문맥을 실제로 읽고 `VERIFIED`(그 sense로 쓰임) / `AMBIGUOUS`(판별 불가) / `REJECTED`(다른 sense·다른 단어·형태 경계 오탐)로 판정한다. **읽지 않은 문맥은 VERIFIED가 아니다.**
5. 창 확장 규칙:
   - 1–4를 읽는다. 가능한 문맥이 남아 있으면 5–8을 반드시 이어 읽는다.
   - 5–8에서 **새로운 의미 결속 독립 관계**가 하나라도 나오면 9–12를 읽는다.
   - 9–12에서도 새 독립 관계가 나오면 13–16을 읽는다.
   - 남은 유효 문맥이 없으면 `no_more_distinct_contexts`를 증거와 함께 기록한다.
6. 종료 사유는 sense별로 기록한다: `inspected_16`, `inspected_all`, `no_more_distinct_contexts`, `no_new_relation_after_N`, `no_verified_context`, `zero_hits`.
7. 검색 결과가 없는 것(`zero_hits`)은 **그 검색 경로에서 미검출**이라는 뜻이며, 말뭉치 전체에 용례가 없다는 증명이 아니다.
8. 검색 실패·인덱스 접근 불가·미판독을 `candidates: []`로 가장하지 않는다. 작업 실패는 실패로 보고한다.

형태 경계 검사: 조회 문맥에서 표제어가 다른 단어의 부분 문자열인지 확인한다. 형태소 분석으로 표제어(또는 `하다/되다` 결합)가 독립 토큰/토큰열로 실현된 문맥만 sense 후보로 남긴다. 이 검사는 자동 판정이 아니라 편집 전처리이며, 최종 sense 판정은 사람이 읽어서 한다.

## 3. PASS B — Exhaustive Discovery (발굴 전용)

각 `VERIFIED` 문맥에서 다음 관점을 **각각** 방문한다.

1. 실제 결합 표현
2. 행동·사건
3. 상황·용례·화자의 역할
4. 원인·결과
5. 대비·연상·감각·이미지

관점마다 (a) 관계 존재 확인 → (b) 발견한 후보를 **전부** 임시 풀에 추가 → (c) 같은 관점의 다른 독립 관계 확인 → (d) 없으면 빈 결과 기록. 발굴 중에는 후보를 2~3개로 추리지 않는다.

**하지 않는 것:** 후보 수 하한·상한, sense당 4개 채우기, 표제어 결합·주변 명사를 그대로 후보로 올리기, 같은 관계를 표현만 바꿔 복제하기.

## 4. PASS C — Pool Assembly / Traceability

- 기존 D 후보(이전 회차) 전체 + 이번 발굴 후보 전체를 sense별로 모은다. 기존 후보에 자동 `KEEP` 권한을 주지 않는다.
- 각 후보는 로컬에서 `source_sense_id, candidate, context_locator, source_surface, sense_evidence, relation_path, derivation, origin(old/new)`를 가진다.
- 정확 중복, 의미 중복, 표제어 exact 후보를 별도 계측한다.
- 기존 후보 전량 또는 신규만 감사하는 지름길을 금지한다.

## 5. PASS D — Adversarial Editing (발굴과 분리 실행)

풀 전체에 동일 기준으로 `KEEP / REWORK / DROP / UNCERTAIN`을 적용한다. 기존·신규를 구분 없이 재판정한다. 각 후보에 다음을 순서대로 적는다.

1. **Exact sense:** Canonical의 그 sense가 원문에서 실제 쓰였는가? 다의어·동음이의어·다른 분야 어의·부분 문자열이 아닌가?
2. **Evidence:** 원문 근거가 source→candidate 관계를 실제로 지원하는가? 같은 문서에 우연히 같이 나왔다는 설명뿐인가?
3. **Writer usefulness:** 작가가 탐색할 자연스러운 관계인가? 직접 동의어일 필요는 없다.
4. **Independence:** 같은 sense의 다른 후보와 의미상 독립적인가?
5. **Strongest counterargument:** 이 후보가 틀렸다면 가장 설득력 있는 근거는 무엇이며, 실제 문맥으로 반박할 수 있는가?

제거 대상: 확실히 다른 sense, 단순 공출현, 오독, 무근거 주변 사물·인물. **보존 대상:** 원문이 지지하는 창의적 비유·감각·장면·느슨한 연상(사전적 등가가 아니라는 이유로 탈락 금지). 판단 불가·원문 불충분은 `UNCERTAIN`으로 남기고 `KEEP`하지 않는다.

표제어 결합(`경제적 이유/풍요/자유/어려움` 류)은 **각각 실제로 구별되는 쓰임을 제공하는지**를 검토한다. 구별되지 않으면 대표만 남긴다.

## 6. PASS E — Repair / Rediscovery

`DROP/REWORK/UNCERTAIN`이 나온 sense를 재방문한다.

- 다른 sense 문맥이면 그 문맥 후보를 모두 재검증하고 올바른 source sense 문맥을 다시 찾는다.
- 단순 공출현이면 그 문맥에서 실제 의미 연결이 있는 행동·사물·상황을 재탐색한다. 더 나은 관계가 없으면 DROP하고 **억지로 대체하지 않는다.**
- 표제어 확장/중복이면 독립적 표현 가치가 있는 관계로 바꿀 수 있는지 재탐색한다.
- 기존 문맥에 답이 없으면 남은 다른 문맥을 검토한다(PASS A의 4→8→12→16 규칙).
- 수정·대체 후보에도 PASS D의 다섯 질문을 다시 적용한다. 수정 횟수·후보 수가 아니라 **새 근거/새 유효 관계 유무**로 종료한다.

## 7. PASS F — Final Quality Gate

- 모든 Canonical sense 방문 여부를 확인한다. 문맥이 없는 sense는 `zero_hits`/`no_verified_context`로 남긴다.
- 실제 `VERIFIED` 문맥 수와 `inspected`(판독) 문맥 수를 혼동하지 않는다.
- 기존 후보 전량과 신규 후보 모두 최종 감사되었는지 확인한다. 기존 후보 100% 유지도 가능하지만, **각 항목의 구체적 근거** 없이는 통과 불가다.
- `REWORK/UNCERTAIN`을 임의 `KEEP`으로 바꾸지 않는다. 미해결 후보는 최종 출력에서 제외하고 별도 집계한다.
- Candidate JSONL v1 구조·순서·중복·source lemma exact 계약을 검증한다.
  - `node scripts/relation/candidate-contract.mjs data/canonical/stdict-<SSS>.jsonl <후보 파일>`

## 8. 실행 비용과 체크포인트

- 더 많은 판독을 허용한다. 비용을 이유로 4/8문맥에서 관성적으로 종료하지 않는다.
- 종료 사유는 검토 문맥 소진 / 마지막 확장 창 신규 독립 관계 0 / 확인 가능한 근거 부재 / 16문맥 완료 중 하나로 기록한다.
- 25–50 record 단위로 로컬 체크포인트를 저장해 컨텍스트 압축·세션 재시작 때 진행·후보·근거가 사라지지 않게 한다.
- 이미 판독한 원문을 무의미하게 재검색하지 않는다.
- 범용 평가 플랫폼·자동 점수·80-sense 블라인드 감사 인프라는 만들지 않는다. 필요하면 로컬 검증 스크립트만 만든다.

## 9. 산출물

- 절차: 이 문서.
- 보고: `RUN.md`에 실제 수치·종료 사유·한계.

## 10. 한계 (모든 배치에 적용)

- 형태 경계 필터는 자동 전처리이며, sense 판정을 대신하지 않는다.
- `zero_hits`는 검색 경로 기준 미검출이다.
- 이 절차가 이미 결과를 본 배치에 적용되면 블라인드 재현이 아니다. 충분히 안정화한 뒤 **새로운 미열람 배치**로 재현성을 확인한다.
