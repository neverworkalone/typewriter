# C Procedure (V9) — 문학 실제 문맥 기반 발굴 레시피

Issue #1061 / #1109, method C(승인된 문학 SQLite의 실제 문맥). 이 문서는 특정 배치의
단어 답안이 아니라 **다른 C 배치에 그대로 적용할 수 있는 생산 절차**다. 원문·발췌문·
SQLite·검색 로그·후보별 근거 상세는 Git에 넣지 않고 로컬 상태에만 둔다.

V9의 목표는 **Stage 2가 되살릴 수 없는 발굴을 최대한 넓게 유지하면서, 후보 문자열의
표현 단위를 단어 중심으로 교정하는 것**이다. 출발 sense의 실제 용례 확인은 엄격하게
하되, 그 용례에서 파생하는 관계의 강도·직접성·창작적 유용성은 보수적으로 재단하지
않는다. 후보 수 목표는 없고 `candidates: []`는 정당하다.

## 0. 최상위 원칙

1. **Stage 1은 발굴, Stage 2는 편집.** type·Tier·채택·target ID를 만들지 않는다.
   KEEP/DROP/Tier를 흉내 내는 gate로 적격한 단어 후보를 대량 삭제하지 않는다.
2. **Recall은 유효하거나 잠재적으로 유효한 고유 관계의 폭**으로 판단하며, 문자열 수나
   균등 분포로 판단하지 않는다. 좋은 후보를 줄여 precision을 올리는 것은 역행이다.
3. **관계 의미의 허용 범위는 넓게, 후보 문자열의 표현 단위는 엄격하게** 관리한다.
   직접 동의어가 아니고 느슨하거나 예상 밖이어도, 정확한 출발 sense의 실제 문맥에서
   의미적 가능성이 있으면 보존한다. 반대로 구체적 사건·용례 서술은 출력하지 않는다.
4. 같은 C 방식 작업을 중복 실행하지 않고, 다른 방식·모델의 후보는 읽지 않는다.
   이전 버전의 **자신의** V5~V8 후보는 회복 자산으로 읽는다.

## 1. 후보 표현 단위 — 출력 형태 기준

**허용 우선순위 (높음 → 낮음):**

1. **단어 / 독립 어휘 항목 — 가장 폭넓게 허용.** 직접 동의어가 아니어도 정확한 출발
   sense의 실제 문맥에서 발견·유도된 의미적 가능성이 있으면 적극 보존한다. 예:
   `검사하다 → 차표 / 수형 / 흉기 / 결산 / 안목`.
2. **짧고 응축된 구·이미지 — 단어보다 좁게.** 그 자체로 독립적인 심상·표현 가치가
   있어 단어 하나로 바꾸기 어려운 경우만. 예: `검은빛 → 검은 새떼 / 움쑥 패인 눈`,
   `검누르다 → 쓸쓸한 길`. 특정 인물·사건을 길게 묘사하는 구는 제외한다.
3. **관용구·고정 결합 — 더 선별적.** 흔히 쓰이고 정착되었다는 사실은 장점이 아니다.
   비상투적인 의미 확장·특별한 심상·뜻밖의 연결일 때만 제한적으로 남긴다.
4. **문장·서술형 절·구체적 사건 설명 — 출력에서 배제.** 완전한 종결 문장뿐 아니라
   `~하다/~되다` 형태로 누가 무엇을 어떻게 했는지 설명하는 용례, 긴 행위·절차·사건·장면
   서술도 제외한다. 예: `걸음걸이 → 난쟁이의 걸음 / 고개를 까댁이며 걷다`,
   `검사하다 → 병아리의 암수를 가려내다 / 회계기의 결산을 맞추다`는 원문 단서로는
   유용해도 최종 어휘 후보로는 부적절하다. 짧다고 해서 사건 서술이 허용되지는 않는다.

**실행 규칙:**

- 각 문맥에서 먼저 연상되는 **단어**를 충분히 열거하고, 그다음 표현 자체로 특별한
  발견 가치가 있는 짧은 구를 제한적으로 검토한다. `source + 동사/수식어`를 기계적으로
  늘리거나 관용구 수집으로 탐색 예산을 소모하지 않는다.
- 긴 원문·사건을 발견했으면 장면에서 독립적으로 연상 가능한 **단어/짧은 심상**을
  추출한다. 억지 축약·새 표현 날조는 하지 않는다. 원문 구절은 로컬 evidence로만 두고
  Candidate에는 응축된 결과만 낸다. 추출할 것이 없으면 문장 후보를 출력하지 않는다.
- 단어가 일상적이라는 이유만으로 제거하지 않는다. 단어가 예상 밖의 source와 맺는
  관계 자체가 새로울 수 있다. 반대로 흔한 관용구를 우대하지 않는다.
- **문법적으로 서술어가 포함되었다는 이유만으로 모든 응축 표현을 자동 금지하지
  않는다.** 독립적인 어휘/표현인가 vs 구체적 사건·용례 서술인가로 판정한다.
- Stage 1은 **형식 적격 여부**만 본다. 적격 단어의 Tier·최종 유용성·관계 강도에 대한
  판정은 Stage 2에 맡긴다.

## 2. PRE-FLIGHT — 동결과 상태

1. Canonical 배치(500레코드)를 읽어 `record_id, sense_id, lemma, pos, gloss,
   search_forms`를 Canonical 순서로 동결하고 record/sense 수, 첫·마지막 ID를 기록한다.
2. Canonical 파일과 문학 인덱스의 SHA-256, 인덱스 계층(FTS5 trigram ≥3자, 2자
   `instr()` 스캔, 실제 포함+단어 시작 경계 재확인)을 기록한다.
3. sense별 상태를 로컬 ledger에 둔다:
   `PENDING → SEARCHED → INSPECTED → BOUND → DISCOVERED → RECOVERED → OUTPUT`,
   실패는 `ZERO_HITS / UNSEARCHABLE / SEARCH_FAILED / NO_VERIFIED / INCOMPLETE`로 구분.
4. 25–35 record마다 체크포인트를 저장한다. 미수행 sense를 빈 후보로 미리 확정하지 않는다.
5. 작은 결정적 파일럿(검색 가능·불가·다의어·이전 후보 포함)으로 도구 오류만 보정하고,
   본 실행 중에는 특정 단어에 맞춰 규칙을 바꾸지 않는다.

## 3. PASS A — sense별 실제 문학 문맥 탐색

- Canonical `search_forms`를 기본으로 하고, 용언·형용사는 `-다`를 뗀 어간과 불규칙
  활용형(ㅂ/ㄷ/ㅅ/ㅎ/ㄹ, `르`·`우`)을 규칙 기반으로 추가한다. 1자 어간은 신뢰할 경계
  검증 경로가 없으면 `UNSEARCHABLE`로 표시하고 용례 없음으로 세지 않는다.
- 3자 이상은 FTS5 trigram, 2자는 `instr()` 스캔으로 검색하고, 실제 문자열 포함을
  재확인한다. 검색 결과는 후보 문자열의 매칭 품질(정확 일치·긴 활용형·경계 일치)로
  정렬해 상위 문맥을 고른다. 작품·작가·장르 다양성을 위해 작품당 최대 2문맥을 선호한다.
- 창 전개: sense마다 우선 1–4를 실제로 읽고 다른 문맥이 남으면 5–8, 유용하거나
  **잠재적으로 유용한** 새 관계가 나오면 9–12, 또 나오면 13–16까지 확대한다.
  문맥을 읽지 않고 숫자만 `inspected`로 세지 않는다. 16문맥 상한과 검색 경로의
  한계는 RUN에 명시한다.
- **출발 sense 결속은 엄격하게:** `VERIFIED`는 실제 텍스트에서 그 Canonical sense의
  사용을 확인한 경우, `AMBIGUOUS`는 다른 작품·문맥으로 재확인 시도, `REJECTED`(다른
  sense/단어/부분 문자열)는 이 출발 sense 후보의 증거가 될 수 없다. 동음이의어·다른
  품사·다른 뜻은 사유와 함께 로컬에 남긴다. 표제어의 다른 sense가 확인된 문맥은
  이 sense의 증거로 쓰지 않는다.

## 4. PASS B — 7관점 OPEN DISCOVERY, 2회 sweep

실제 VERIFIED 문맥마다 다음 7관점을 적용한다(이 단계에서는 가치 판정을 하지 않는다).

1. **Image** 색·모양·빛·대상·시각적 변화
2. **Action** 동작·몸짓·행동·반응
3. **Emotion** 정서·태도·심리 변화
4. **Sensation** 소리·촉감·냄새·맛·온도·신체감각
5. **Scene/Situation** 장면·서사·시공간·사건
6. **Causality** 원인·결과·변화의 파급
7. **Metaphor/Contrast** 비유·상징·대조, 느슨하거나 예상 밖의 연상

관점마다 (a) 문맥 읽기 → (b) 명시·간접·느슨한 이미지·대비까지 탐색 → (c) 후보 풀에
저장 → (d) 다른 가능성 한 번 더 탐색 → (e) 없으면 0 기록. 첫 후보에서 멈추지 않는다.

- **원문 표현, 활용형, 문맥에서 자연스럽게 떠오르는 작가의 선택지**를 함께 모은다.
  한 작품에서만 나온 비유·의외의 감정·느슨한 연결도 의미적 가능성이 있으면 보존한다.
- **다양한 연결을 1개로 축약하지 않는다.** 같은 장면의 시각·색·몸짓·정서·결과가 각각
  작가의 선택지면 각각 남긴다. 시점·어조·강도·이미지가 다른 유사 표현도 보존한다.
- 후보마다 로컬에 `sense_id, context_locator, textual_anchor, lens, candidate,
  derivation(exact|inflected|inferred), connection_hint, discovery_pass`를 남긴다.
  `connection_hint`는 설명용이며 완전한 인과 증명서가 아니다. 강한 설명을 쓰기 어렵다는
  이유로 후보를 버리지 않는다.
- **두 번째 독립 sweep을 반드시 수행한다.** 전체 VERIFIED 문맥에 7관점을 다시 적용하되
  1차 결과를 답안으로 고정하지 않고, 누락된 새 관계·대비·이미지와 **표현 단위 위반**을
  함께 찾는다. 2차 sweep에서는 문장·사건 후보를 단어/짧은 구로 환원하거나 제거한다.

## 5. PASS C — 이전 버전에서 잃은 후보 회복

- 자신의 V5/V6/V7/V8 후보 문자열을 `sense_id + 정규화 candidate`로 합쳐 복원한다.
  특히 이전 버전의 편집상 DROP/REWORK는 Stage 2의 최종 판정이 아니므로 되돌린다.
- 이전 후보도 V9 표현 단위 검사를 통과해야 한다. 약한 단어 연상은 회복하되, 문장/사건
  설명은 `FORM_EXCLUDED`, 실제로 단어·응축 구를 추출할 수 있으면 `FORM_EXTRACTED`로
  귀속한다. 회복 대상이라고 해서 부적절한 문장형 표현까지 자동 복원하지 않는다.
- 완전히 잘못된 source sense, 읽지 않은 문맥에 의한 오탐, 글자 부분 일치, 지어낸 원문
  같은 **기술적 결함만** 제거한다.
- 실제 VERIFIED 문맥이 있고 형식 적격이면 약하거나 DROP 가능성이 높아도 유지한다.
  근거 로그가 없으면 문맥을 재조회·재발굴한다. 끝내 해당 sense의 실제 용례를 확보하지
  못한 항목은 출력에서 빼고 `STILL_UNVERIFIED_SOURCE`로 보고한다(편집상 품질 DROP이 아님).

## 6. PASS D — 최소 Stage 1 hygiene

- **수정/제외 가능(하드):** 정확한 record/sense 결속, 다른 단어·다른 sense, 부분 문자열
  오탐, 존재하지 않는 원문·locator 날조, 출발 lemma와 정확히 같은 후보, 동일 sense 내
  정규화 정확 중복, 빈/깨진/허용 불가 형식, Candidate v1 위반, 설명 가능한 연결이 전혀
  없는 순수 주위 명사·임의 문자열.
- **형식 gate:** 독립 단어/응축 구가 아닌 서술형 절·구체적 장면·사건 설명을 제거하고,
  가능하면 그 원문에서 단어/짧은 심상을 추출한다. `FORM_EXCLUDED / FORM_EXTRACTED`로
  로컬 기록. 이 gate는 후보의 **표현 형태**를 제어하며, 적격 단어의 약한 의미 관계를
  판정하거나 Tier/Drop을 정하는 편집 gate가 아니다.
- **삭제 금지(소프트):** 느슨한 이미지·정서·비유, 좁고 개인적인 문맥, 원문/유도 중
  어느 쪽이 더 좋은지, 의미가 가까운 후보 여러 개(정확 중복 제외), 단순해 보이지만
  작가에게 유용할 수 있는 표현, Stage 2가 낮은 Tier로 보낼 약한 후보.
- 상태는 로컬 ledger에만 기록하고 Candidate JSONL에는 confidence/quality/tier/state를
  넣지 않는다.

## 7. PASS E — 실행 완전성과 출력

1. Canonical 배치 500레코드/전체 sense의 순서·ID·모든 sense 보존, 후보 배열 구조 계약.
2. 검색 실패·미완료를 정상 `[]`로 위장하지 않았는지, VERIFIED·inspected 계수가 맞는지,
   창 전이와 7관점 1·2차 sweep을 실제로 했는지 확인한다.
3. 이전 후보 전량의 lineage를 `RECOVERED / RETAINED / FORM_EXTRACTED / FORM_EXCLUDED /
   TECHNICAL_EXCLUDED / STILL_UNVERIFIED_SOURCE / EXACT_DUPLICATE`로 귀속하고,
   실질 후보를 없앤 이유가 기술 오류 또는 표현 형태에 한정되는지 개수 정합성을 확인한다.
4. 단어/응축 구/관용·고정 표현/서술형 제외/서술→단어 추출 건수, 관계 관점 다양성,
   sense 활성 분포를 기록한다. 총 후보 수나 억지 균등 분포는 합격 조건이 아니다.
5. `node scripts/relation/candidate-contract.mjs`의 `validateCandidateBatch` 계약을
   통과해야 한다(실험 경로 산출물은 경로 검사 대신 batch 검증 함수를 직접 호출하고
   그 사실을 RUN에 밝힌다).
6. 상세 evidence 로그는 로컬만. PR에는 원문·DB·검색 로그를 넣지 않는다.

## 9. 사용자-facing 생산 프롬프트(짧게)
