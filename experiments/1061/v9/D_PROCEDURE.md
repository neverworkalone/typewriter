# D V9 절차 — 단어 우선 회복 + 후보 문장 0개 절대 조건

이 문서는 Issue #1106의 **D V9** 실험 절차다. 목표는 Stage 2의 채택/제외·Tier·type을 미리 흉내 내는 것이 아니라, 승인된 문어 말뭉치(승인된 문어 말뭉치 SQLite + bigram postings, read-only)의 실제 용례에서 **강한·중간·약한 의미 가능 관계를 단어 중심으로 가능한 한 많이** 확보하는 것이다. 동시에 V8에서 문제가 된 **서술형/문장형 후보를 최종 산출물에서 0개로** 만든다.

이 문서는 이 배치의 결과 파일이나 특정 단어 목록에 의존하지 않으며, 처음 보는 배치에서도 같은 순서로 실행할 수 있도록 검색·판독·발굴·회복·표현 형식 검사·출력 단계를 정의한다. 실행에 쓰는 스크립트와 경로는 §7에 둔다.

## 0. 역할 경계

- Stage 1(D)은 **candidate generation**만 한다. `record_id`, `senses[].sense_id`, `senses[].candidates` 외의 필드를 넣지 않는다.
- Tier·relevance·relation type·target ID·keep/drop·admission은 Stage 2의 결정이다. 이 절차는 그것을 예측하거나 모방하지 않는다.
- 다른 생산자(Codex/Claude)나 다른 방식(C)의 후보·문맥·평가를 읽지 않는다. 오직 **같은 생산자(D)의 이전 버전(V4–V8)** 만 회복 입력으로 쓴다.
- 승인된 문어 말뭉치 SQLite·postings·FTS는 read-only로만 쓴다. 원문·발췌·검색 로그·ledger·SQLite는 Git/PR/제품에 넣지 않는다.

## 0.1 절대 금지 규칙 — 최종 후보에 문장 0개 (NON-NEGOTIABLE)

**MANDATORY / ZERO-TOLERANCE.** 최종 `senses[].candidates[]`에 **문장·서술형 절·사건/과정 설명을 단 한 개도 넣지 않는다.** 이 규칙은 recall-first, 과거 후보 복원, 원문 인용, 느슨한 연상 보존, 실제 corpus 용례 및 기타 소프트 지침보다 **우선한다**. *원문에 실제로 등장했다 / 출발 sense에 맞는다 / 짧다 / 글쓰기 이미지가 좋다 / Stage 2가 Drop할 수 있다*는 **예외 사유가 아니다.** 한 건이라도 남으면 산출물 불합격이다.

금지 예(단어만 바꾼 동형 사례에도 동일 적용):

| source | NEVER output | 이유 |
| --- | --- | --- |
| 격벽 | `격벽을 여는 데 에너지가 필요하다` | 완전한 설명문 |
| 결탁되다 | `택시기사와 공무원이 결탁되다` | 사건 서술 |
| 격분하다 | `격분하다가 식판을 뒤엎다` | 일어난 일의 시간순 서술 |
| 결정화하다 | `수면을 추출하여 결정화하는 기술` | 과정 설명의 명사구 포장 |
| 검사하다 | `병아리의 암수를 가려내다`, `회계기의 결산을 맞추다` | 구체적 실행 사례 설명 |
| 걸음걸이 | `고개를 까댁이며 걷다`, `난쟁이의 걸음` | 특정 행동·장면 묘사 |

**우회 금지:** 마침표 제거, 어미 생략, 종결형→관형형 변환, 뒤에 `일/장면/기술/상황` 붙여 명사구화, 출발어 끼워 넣기, 문장 절반 자르기 모두 금지. **완결된 사건 또는 설명의 뼈대가 남으면 문장형으로 취급하고 배제한다.**

**허용 형태:** (A) 단어 — 가장 넓게 수집. (B) 독립된 이미지가 있는 짧고 응축된 **비서술적** 구 — 발견 가치가 있을 때만 제한적으로. (C) 흔한 관용구/고정 결합 — 고정되어 있다는 사실 자체는 가치 근거가 아니며, 특별한 발견 가치가 있을 때만. 관용구라고 포장한 서술문은 금지.

**실행 필수:** PASS B에서 원문 문장을 후보로 복사하지 않고 연상 단어를 먼저 추출한다. PASS C에서 과거 후보를 복원하되 문장형은 `FORM_EXCLUDED`, 별도 단어/구로 뽑았으면 `FORM_EXTRACTED(old→new)`로 계보 기록한다. PASS D에서 모든 후보 문자열을 하나씩 읽고 0건 검사를 한다(자동 validator 통과만으로 대체하지 않는다). PASS E와 RUN.md에 `final_sentence_or_event_description_count = 0`을 명시한다.

## 0.2 후보 표현 단위 — 단어 우선 / 발견 가치 기준

1. **독립 단어 — 가장 폭넓게 발굴·보존.** 느슨하거나 평범한 단어라도 특정 source sense와 예상 밖의 연결을 만들면 허용한다. 단어가 흔하다는 이유로 제외하지 않는다.
2. **짧고 응축된 구·심상 — 단어보다 좁게.** 단어 하나로 드러나지 않는 구체적 심상·특별한 연결일 때만 보존한다. 사건 참여자·행동을 길게 기술한 용례와 혼동하지 않는다. (V9 결과에서는 다어절 응축 구 0개 — 단어 우선 원칙의 자연스러운 결과.)
3. **관용구·고정 결합 — 더 제한적으로.** 흔하고 익숙하다는 이유로 우대하지 않되, 발견 가치가 있으면 단일 토큰 어휘로 보존한다.
4. **문장·서술형 절·사건/행동 설명 — 최종 후보에서 배제.**

**형식 판단은 어절/글자 수·품사·`하다` 유무의 기계적 컷오프가 아니다.** 독립적 단어/응축 표현인지, 그때그때 일어난 사건·행동을 길게 기술한 용례인지 구별한다. 형식 판단을 통과한 **단어 후보의 약한 의미 관계는 Stage 2로 넘긴다.**

## 1. PRE-FLIGHT

1. `MODE=CALIBRATION`, `SHARD`, `BATCH`, `RUN_ID`, 모델, 절차 버전과 SHA, Canonical SHA-256, 코퍼스 인덱스 SHA-256, 시작 HEAD, 출력 경로를 기록한다.
2. Canonical 배치의 record 순서와 모든 sense(`lemma`, `pos`, `gloss`, `search_forms`, `sense_id`)를 동결하고 수를 센다(016/01 = 500 records / 565 senses).
3. 로컬 ledger 디렉터리를 만들고 25–50 records마다 checkpoint한다. 중단·재개 시 미완료 sense를 `[]`로 위장하지 않는다.
4. deterministic pilot(수십 records)로 검색·형태소·검증 결함을 먼저 고치고 절차를 동결한다. 단어별 예외 목록이나 후보 수 할당량을 두지 않는다.
5. 도구: 문어 말뭉치 FTS는 **trigram**이라 2자 이하 질의가 0을 반환할 수 있다. 짧은 표제어는 sidecar **bigram postings** 또는 `instr` LIKE로 조회한다. 형태소 분석은 khaiii(v0.4, macOS arm64)를 로컬 경로에서 직접 로드한다.

## 2. PASS A — 실제 사용 문맥 확보

### 2.1 검색형 생성 (일반 규칙)

표제어·`search_forms`에서 다음을 **일반 규칙으로** 생성한다.

- 표제어, 띄어쓰기 제거형, 다어절 표제어의 내용 토큰
- `하다`/`되다`/`시키다` 활용: 어간, `-하/해/했/한/할/합/한다/했다/하면/하며/하고/해서/하기/하여/되었/된다/됐/되면/되기/되어/시키/시켜/시킨`
- 일반 용언: 어간과 생산적 어미, 대표적 불규칙 활용 보충
- 동일 표제어 안의 여러 sense는 같은 검색 pool을 공유하되 판정은 sense 단위로 따로 한다.

### 2.2 probe 순서 (재현성의 핵심)

검색은 **표제어와 기본형을 먼저, 파생 활용형을 나중에** probe한다. 긴 파생형만 먼저 probe하면 실제 문맥을 놓친다. probe 수·rowid 수에 상한을 두고, rowid가 충분히 모이면 중단한다. 짧은 probe(2자 이하)는 bigram postings/LIKE, 3자 이상은 FTS를 쓴다.

### 2.3 후보 문맥 구성

- 문맥 locator(`d{document}:p{paragraph}`), 문서 제목·저자·날짜, 일치 표면형, 일치 위치, 원문 단락을 기록한다.
- 문서당 최대 2문맥을 우선해 최대 40문맥을 준비한다(중복 문맥 제거).
- 순위는 (a) 표제어와 정확히 같은 표면형, (b) 토큰 경계 일치, (c) 긴 표면형, (d) 적당한 길이의 단락을 가중한다. 다른 단어 안의 부분 문자열은 감점하되 버리지 않는다.
- 실제 판독은 4문맥 창부터 시작해 4→8→12→16으로 확장한다. 새 관계가 없으면 `saturated_4`/`saturated_8`로 중단 사유를 기록한다. 첫 후보 2–3개에서 임의 종료하지 않는다.

### 2.4 zero-hit / no-verified 재시도 사다리

검색 미검출 sense는 다음을 **순서대로** 시도하고 시도·결과를 기록한다.

1. 표제어·`search_forms` 기본 probe 재실행
2. §2.1의 활용형·불규칙형·띄어쓰기·합성어 변형
3. 어간·기본형 우선 probe 순서로 재검색(§2.2)
4. 다른 승인 인덱스/검색 경로(FTS ↔ bigram postings ↔ 부분 문자열 조회)
5. 문맥 단위 재조회 및 문서 다양성 확대

재시도 후에도 실제 용례가 없으면 정당한 `ZERO_HITS`, 검색 자체가 실패하면 `SEARCH_FAILED`, 원문이 없으면 `UNSEARCHABLE`로 남긴다. 좁은 검색어를 무작정 부분 문자열로 풀어 오탐만 키우지 않는다.

### 2.5 문맥 판정

각 문맥을 실제로 읽고 **출발 sense 기준**으로 판정한다.

- `V`(VERIFIED): 정확히 이 sense의 쓰임이라는 긍정 증거
- `A`(AMBIGUOUS): 둘 이상 sense가 가능
- `R`(REJECTED): 다른 sense·동음이의어·다른 단어 활용형·부분 문자열 오탐, 또는 표제어와 `search_forms` 밖의 활용형

자동 판정 기준: 일치 위치의 토큰이 표제어(명사는 꼬리 조사 허용, 다어절/표현은 완전 일치 필요)와 정합해야 한다. 다의/동음이의 record가 같은 문맥을 공유하면 gloss 토큰 겹침이 2 미만일 때 `A`로 두고 **수동 판정**한다. `V`가 없으면 문맥이 있으면 `NO_VERIFIED`, 문맥 자체가 없으면 `ZERO_HITS`다. `V` 수는 읽은 문맥 수와 별도로 센다.

## 3. PASS B — 다섯 관점 발굴 (단어 중심, 1·2차 sweep)

`V` 문맥마다 다음을 **별도로** 순회한다.

1. `coll`: 자연스러운 결합 표현·실제 공기·고정 표현에서 연상되는 **단어**
2. `act`: 동작·행동·사건과 그 주체·대상·역할에서 연상되는 **독립 단어**
3. `scene`: 특징적인 상황·장면·시간·장소·결과에서 뽑는 **단어·응축 이미지**(사건 설명 복사 금지)
4. `cause`: 원인·결과·대응·변화
5. `assoc`: 대비·감각·이미지·느슨한 연상

각 관점에서 (a) 원문을 다시 읽고 (b) 명시·간접·가능성 있는 연결을 찾고 (c) 후보 문자열을 pool에 넣고 (d) 놓친 다른 관계를 재확인하고 (e) 없으면 0을 기록한다. **후보 문자열은 단어 우선**으로 응축하며, 문장·사건 설명은 pool에 넣지 않는다.

**1차 sweep (구현):** 각 `V` 문맥의 판독 창(window)을 형태소 분석해 내용 형태소(NNG/NNP/VV/VA/MAG)를 추출하고, 일치 위치와의 거리로 가중한 점수로 sense별 상위 24개 토큰을 만든다. `source lemma`와 겹치는 토큰, 불용 기능어는 제외한다.

**2차 sweep (구현):** 1차에서 상위 24개에 들지 못한 토큰(rank 25–96)과 **바깥 창**(거리 220–420자) 토큰을 별도로 집계한다. 1차 목록을 다시 쓰는 것이 아니라 **새로운 결합·행동·상황·인과·대비**를 찾는 순회다. 새로 검토한 토큰과 실제로 후보에 채택한 수를 관점별로 로컬에 기록한다. 새 후보가 없으면 0으로 보고하며 **인위적 할당량은 없다.**

후보마다 로컬 ledger에 다음을 남긴다: `sense_id, context_locator, source_surface, sense_binding, lens, candidate, form(exact|inflected|inferred), connection_hint, source_version`. 약한 관계에 완전한 인과 증명을 요구하지 않되, "같은 문단에 있음"은 경로가 아니다.

**금지:** 뜻풀이를 그대로 옮긴 조각, 표제어+일반 수식어의 기계적 결합으로 개수 늘리기, 근거 없는 무작위 문자열, **그리고 문장·서술형 사건/과정 설명.**

## 4. PASS C — 이전 버전 회복 (형태 적격 단어만)

- 같은 생산자의 **V4/V5/V6/V7/V8 후보 전체**를 `sense_id + candidate` 키로 모아 이번 발굴과 union한다. 단 **적격한 단어·짧은 표현만** Candidate로 회복한다.
- **V8의 문장형·다어절 후보는 전부 `FORM_EXCLUDED`.** 이 배치의 V4–V8 후보 중 953개 다어절(문장/구) 문자열과 102개 조각(fragment) 문자열이 여기 해당한다.
- **이전 우선순위:** sense의 `V8` 후보 목록이 있으면 그것을 기준으로 하고(=`RETAINED`), V8에 없는 V4–V7 단어(`prior_old`)는 **형태 적격이고 명백한 오결속이 아닐 때 회복**한다(= `RECOVERED`). V8이 이미 버린 하드 오류(예: 격변→`상징`, 격분→`수간호사`)는 회복하지 않고 blocklist로 남긴다.
- 오결속 판정: 이전 단어가 출발 sense와 무관한 동음이의/다른 sense 문맥에서 온 경우 `SOURCE_UNVERIFIED`로 제외하고 사유를 남긴다.
- **약한 연상·간접 관련·중복 우려·Stage 2 Drop 가능성은 Stage 1 배제 사유가 아니다.** 실제 `V` 문맥에서 설명 가능한 연결이면 회복한다.
- 문장형에서 별도 단어·구를 뽑았으면 `FORM_EXTRACTED(old→new)`로 로컬 기록한다. 무리한 변형은 금지한다.
- 이전 ledger가 없으면 다른 검색 경로로 다시 조회한다. 검증 없이 자동 유지하거나, 편집상 의심만으로 무차별 삭제하지 않는다.

## 5. PASS D — 최소 기술 품질관리 + 표현 형식 검사 (편집 gate가 아님)

**하드 제외/수정:**

- 다른 `record_id/sense_id`, source sense와 무관한 문맥, 확실한 부분 문자열·형태 분석 오탐, 존재하지 않는 근거
- 정확한 출발 lemma와 동일 문자열 및 **띄어쓰기만 다른 표제어 변형**, lemma+괄호 전용 변형
- **비어휘 형식:** 숫자·수량·연도 표기(예: `120근`, `1표`, `3중`, `20도`, `1960년대`), 복수 접미 파생형 조각(예: `결의론자들`)
- 같은 sense 안 정확 중복(공통 normalizer), 빈 조각·계약 위반·깨진 형식
- `V` 문맥에서 설명 가능한 관계가 전혀 없는 임의 생성 문자열

**표현 형식 gate (Stage 1 출력 형태):** 단어 최대 허용 / 응축된 구 선별 / 흔한 관용구·고정 결합 비우대 / **문장·사건 설명 배제**. 원문 서술형 후보에서 가능하면 연상 단어를 다시 추출한다. 로컬 감사에 `FORM_EXCLUDED / FORM_EXTRACTED(old→new)`와 원문 evidence locator를 남긴다.

**전수 검사(필수):** 최종 JSONL의 **모든 후보 문자열을 하나씩 읽고** 문장·서술형·사건/과정 설명 0건을 확인한다. 어절 수·정규식만으로 통과 판정하지 않는다. 위반을 1건이라도 발견하면 수정하거나 제거하고 **다시 전수 검사**한다.

**Stage 2로 이양(Stage 1에서 제거하지 않음):**

- 가볍거나 약한 배경·상황이라는 주관적 판단
- 근접 의미의 여러 표현(정확 중복이 아닌 경우), 향후 Tier·가치 순위
- 원문/활용형/유도 표현 중 어느 쪽이 더 좋은지
- Stage 2에서 Drop될 가능성이 높아도 문맥과 연결 가능한 후보

`UNCERTAIN_SOURCE`(출발 sense 미확인)는 재검색 후에도 미확인이면 보존 불가, `UNCERTAIN_EDITORIAL`(관계 강도·작가 가치 판단 어려움)은 후보로 보존한다. 이 구분은 로컬 ledger에만 적고 Candidate v1에는 상태·confidence·Tier를 넣지 않는다.

## 6. PASS E — 검증과 출력

- 500 records(마지막 배치는 83)·전체 sense·ID·순서, Candidate v1 스키마(`record_id`, `senses[].sense_id`, `senses[].candidates`만)
- 모든 sense에 status, `V` 문맥에 provenance, `A/R`에 후보 없음
- 같은 sense 내 정규화 중복 없음, 표제어 exact/변형 없음, trimmed nonempty
- 이전 버전 후보 계보: `RETAINED / RECOVERED / TECHNICAL_EXCLUDED / SOURCE_UNVERIFIED / FORM_EXCLUDED / FORM_EXTRACTED / EXACT_DUPLICATE / REWORKED` 집계 일치
- `zero_hits`/검색 실패/`INCOMPLETE`를 `[]`로 가장하지 않음
- 원문/활용형/유도 구성, 결합·행동·상황·인과·연상 다양성. **단어/응축 구/관용·고정 표현/서술형 제외/서술→단어 추출** 개수와 일반 오류 유형을 별도 보고한다.
- **전 후보 문자열 수동 형식 검사 + `final_sentence_or_event_description_count = 0`을 RUN.md에 명시**
- 일정 후보 수·균등 분포를 합격 조건으로 삼지 않는다.

기계적 gate 통과는 의미 품질 인증이 아니다. 최종 판단은 별도 평가 단계에 맡긴다.

## 7. 실행 파이프라인 (V9에서 실제로 사용)

1. **검색** `search.mjs` → `hits.jsonl`(sense별 문맥), `search.out`(총계). FTS trigram + short bigram postings + LIKE 사다리, 표제어 우선 probe 순서, 문서당 ≤2문맥, sense당 ≤40문맥.
2. **1차 추출/판정** `extract.py`(khaiii) → `analysis.json`, `review.json`. 문맥 판정(V/A/R), sense status, 창 형태소 상위 24토큰, 이전 버전 후보 분류(V8 단어=`prior_words`, V4–V7 전용 단어=`prior_old`, 다어절=`prior_phrases`).
3. **2차 추출** `sweep2.py` → `analysis2.json`(rank 25–96 + 바깥 창 220–420자 토큰).
4. **리뷰 digest** `prepare_review.py` → `digest_00..05.txt`(1차), `digest2.txt`(2차). gloss·status·현재 후보·신규 토큰만 보여 주고 원문은 넣지 않는다.
5. **수동 리뷰/판정** → `decisions/part00..05.json`(1차: `{sense_id:{ok, add}}`), `adds_second.json`(2차: `{sense_id:[단어]}`).
6. **조립/형식 검사** `merge.mjs` → `merged.jsonl` + `audit.json`. 정규화(NFC·공백), 표제어 exact/변형 제외, 정확 중복 제거, 비어휘 형식 제외, 전수 문자열 스캔.
7. **검증** `validate.mjs`가 repo의 `validateCandidateBatch`를 import해 `batch=01`로 검사(경로 제약 때문에 CLI 대신 export 함수 사용).

**산출:** `experiments/1061/v9/D_PROCEDURE.md`, `016_01_d_deepseek.jsonl`, `RUN.md`. Candidate JSONL에는 `record_id`, `senses[].sense_id`, `senses[].candidates`만 넣는다.

## 8. 로컬 ledger 형식

JSONL 한 줄에 record 하나.

```json
{"record_id":"w00000","senses":[{"sense_id":"w00000-s1","stop":"inspected_4","ctx":[["c1","V","증거"],["c2","R","다른 sense"]],"lens":[["c1","11101"],["c1","00010"]],"form":[["문장형 후보","FORM_EXCLUDED","c1"],["핵심어","FORM_EXTRACTED","c1"]],"new":["후보"],"old":[["이전 후보","RETAINED","c1","관계"]]}]}
```

- `ctx`: `[context_id, verdict, evidence]`
- `lens`: `[context_id, "coll/act/scene/cause/assoc 5비트"]`(1차), `[context_id,"2","...","S2"]`(2차)
- `form`: `[후보, FORM_EXCLUDED|FORM_EXTRACTED, context_id]`
- `new`: 이번에 발굴한 후보, `old`: 이전 버전 후보의 계보 판정

## 9. 한계

- 개발/calibration 배치(016/01)는 이미 결과를 본 비블라인드 배치다.
- 검색 자료는 문학 문어에 치우쳐 있다.
- `ZERO_HITS`는 해당 검색 경로의 미검출이지 말뭉치 전체 부재의 증명이 아니다.
- 2차 sweep의 바깥 창 토큰은 노이즈 비율이 높아 채택률이 낮다.
- 최종 후보의 작가 유용성·정확성은 독립 평가가 필요하며, 이 절차의 기계적·수동 검사는 그것을 대체하지 않는다.
