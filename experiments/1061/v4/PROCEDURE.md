# D 생산·검증 절차 V4 — 의미 감사와 편집 선택

V3는 발굴량을 늘렸지만, 같은 sense 안의 의미 중복과 sense 오류·공출현 후보도 함께 늘렸다. V4는 **기존 후보 전수 의미 감사 → 의미 군집화 → 문맥 재분석 발굴 → 표제어 포함 후보 정리 → 최종 재검증** 순서로, 후보 수가 아니라 **독립적인 관계의 수**를 높인다. 특정 표제어를 위한 예외는 두지 않는다.

## 1. 입력과 고정 조건

- Candidate JSONL v1 계약, `docs/relation-factory.md`의 D 목적 유지.
- 검색 상태 구분(`ok` / `zero_hits` / `zero_after_filter` / `search_failed`) 유지.
- 원문·문단 ID·검색 로그는 저장소 밖.
- **가능하면 직전 회차의 검색 문맥을 고정**하고 편집 개선 효과를 먼저 측정한다. 추가 검색은 기존 문맥으로 관계를 확보하지 못할 때만 한다.

## 2. Phase A — 전수 의미 감사

모든 후보를 세 축으로 독립 평가한다.

1. **Sense accuracy** — 정확한 source sense와 연결되는가. 동음이의어·다른 sense·원문 의미 왜곡이 없는가.
2. **Context grounding** — 실제 문맥으로 설명 가능한가. 원문 그대로인지 문맥 유도인지 구분되는가. 단순 공출현을 넘는가.
3. **Editorial value** — 작가에게 표현 선택지나 연상을 주는가. 같은 sense의 다른 후보와 독립적인가. 출발어를 길게 재작성했을 뿐인가.

판정은 셋 중 하나다.

- **KEEP** — 세 기준 충족.
- **REWORK** — 문맥 근거는 유효하나 추출 방식이 부적절. 같은 문맥에서 독립 표현을 다시 뽑는다.
- **DROP** — 의미 오류, 무근거, 공출현, 뜻풀이 반복, 회복 불가능한 중복.

Drop 사유는 내부적으로 `SENSE / CONTEXT / GLOSS / COOC / LEMMA / FRAG / DUP` 중 하나로 기록한다. 문자열 필터로 제거하지 않는다.

## 3. Phase B — 의미 군집화

같은 sense의 후보를 **제공하는 정보** 기준으로 묶는다.

- 같은 정보의 변형(예: `X를 이루다 / X를 가지다 / X를 보이다`)은 대표 하나만 남기거나, 실제로 구별되는 다른 관계로 대체한다.
- 상황·행동·결합·원인·결과·대조가 서로 다르면 모두 유지할 수 있다.
- 문자열이 다르다는 이유로 별개 관계로 세지 않는다.

## 4. Phase C — 문맥 재분석 발굴

DROP/REWORK를 처리한 뒤, 남은 후보가 적은 sense부터 **이미 확보한 문맥**을 다시 읽고 다음을 확인한다.

1. 실제 사용 표현·의미 있는 결합
2. 구체적 행동·사건
3. 사용 상황·전형적 맥락
4. 원인·결과
5. 의미상 대조·문맥 기반 연상

기존 문맥으로 부족할 때만 다른 문서의 문맥을 추가 확보한다. 추가 검색으로 얻은 후보는 별도로 기록해 **검색 recall 효과와 편집 개선 효과를 분리**한다. 억지로 채우지 않는다.

## 5. Phase D — 출발 표제어 포함 후보

출발어 포함 여부만으로 제거하지 않는다. 다음을 구분한다.

- 독자적 가치가 있는 관용구·전형적 결합·전문 용어 → 유지.
- 출발어에 조사·형용사·총칭만 붙인 평범한 표현 → 제거.
- 출발어와 함께 나타나는 행동·사물·상황 → **출발어를 뺀 독립 후보로 재추출**.
- 문장 일부를 그대로 옮긴 표현 → 관계 가치가 없으면 제거.

재추출 후보는 해당 문맥에서 의미 관계가 확인될 때만 채택한다.

## 6. 최종 재검증

출력 직전에 후보별로 다시 확인한다: sense 결속, 문맥 근거, 독립 편집 가치, 같은 sense 내 의미 중복, 표제어 포함 정당성, 이전 회차 오류 유형의 재발.

자동 검사는 계약 위반만 잡는다: 같은 sense 정확 중복, source lemma와 정확히 같은 문자열, 비어 있지 않은 trimmed 문자열, `search_failed` 부재. **자동 계약 통과를 의미 품질 검증으로 보고하지 않는다.** 의미 판정은 별도 감사로 남긴다.

## 7. 보고

- 총 후보, 후보 있는 sense, 활성 sense당 평균.
- 이전 회차 후보의 KEEP / REWORK / DROP 수와 DROP 사유 분포.
- 기존 문맥 재분석 신규 후보 수와 추가 검색 신규 후보 수(분리).
- 표제어 포함 후보의 유지·제거·재추출 결과.
- 독립 관계 수(군집화 후 후보 수)와 sense당 분포.
- 남은 오류·검증 한계, 검색·판독 비용.
- 제거 수 자체를 성과로 보고하지 않고, **나쁜 후보를 좋은 후보로 대체한 결과**를 보고한다.
