#927 Stage 2 진행해

War Room이 지정한 Part (Shard {{shard}} · Batch {{batch}} · Part {{part}})를 처리한다.
현재 worktree와 브랜치 {{branch}}를 그대로 사용한다.
Part를 다시 선정하거나 브랜치를 변경하지 않는다.
War Room이 준비한 HEAD를 기준으로 작업하며,
편집 도중 master가 갱신되어도 현재 브랜치를 merge/rebase/reset하지 않는다.

Issue #927의 Stage 2 admission 계약과 docs/relation-factory.md, docs/relation-editorial-policy.md를 읽고 준수한다. 새로운 후보 발굴은 하지 않는다.

절차는 다음과 같다. 셸 명령은 개별로 실행해 각 종료 코드와 출력을 확인한다.
1. `node scripts/relation/admission-cli.mjs prepare --shard {{shard}} --batch {{batch}} --part {{part}} --out .warroom-scratch/{{shard}}_{{batch}}_{{part}}.json` 로 이 Part의 편집 항목을 만든다.
2. 이 Part의 항목만 편집해 `data/relations/relation-{{shard}}.jsonl`, `data/relation-drops/drop-{{shard}}.jsonl` 에 누적한다. 기존 승인 데이터와 다른 Part의 행은 보존하고, 다른 샤드·Candidate 파일·Canonical은 수정하지 않는다.
3. `node scripts/relation/admission-cli.mjs verify --shard {{shard}} --batch {{batch}} --part {{part}}` 가 통과할 때까지 수정한다.
4. 커밋·push하고 `batch` 라벨의 PR 하나를 제출한다. PR 생성 직전 같은 샤드의 열린 Stage 2 PR이 없는지 확인한다. PR 본문에서 #927을 참조하거나 닫지 않는다.

PR 제출 후 종료한다. 리뷰·머지 감시, 머지 후 최신 master 검증과 다음 Part 실행은 War Room이 담당한다. 다른 모델·CLI·서브에이전트를 실행하지 않는다.

임시·스크래치 파일(검증용 스크립트, 청크, probe 결과 등)은 worktree 안의 `.warroom-scratch/` 에만 만든다. 이 디렉터리는 git에서 무시되며 커밋하지 않는다.
산출물이 아닌 파일을 worktree의 다른 경로에 남기지 않는다.

공통 결함(반복 가능한 공유 계층 결함)을 확인하면 `tools/warroom/prompts/shared-defect.md` 형식으로 `.warroom-scratch/shared-defect.json` 에 보고하고 멈춘다.
