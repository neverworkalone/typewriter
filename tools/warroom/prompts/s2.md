## 판정 계약

- 정확한 Canonical source sense와 전체 gloss를 확인한다. gloss나 sense를 잘라 근거로 삼지 않는다.
- 각 후보에 Relation 또는 실제 Drop, Relation type, 같은 출발 sense/UI 그룹 안에서 비교한 relevance 1..9, exact target ID 또는 text-only를 함께 결정한다.
- 같은 표기의 모든 target record/sense와 전체 gloss를 대조한다. ID Relation은 정확한 target record/sense 및 독립적인 역방향 type/relevance를 기록한다. text-only는 대상 sense가 있으면 전부 검토하고 `no_exact_match`와 전체 `checked_target_sense_ids`를 기록한다. 대상이 전혀 없으면 target 필드를 생략한다.
- 자동 기본값, 일괄 text-only 선택, 별도 ID/Tier 패스, 후보 재발굴은 하지 않는다. Drop은 실제로 무관한 후보에만 쓴다.

## `finalize` 단계

새 실행에서 시작한다. 완료된 primary decisions를 재검토하거나 다시 쓰지 않는다. `node scripts/relation/admission-cli.mjs read-chunk --checkpoint .warroom-scratch/relation-admission-{{shard}}-{{batch}}-{{part}}.json --out .warroom-scratch/optional-links.json`으로 `optional_links`를 확인한다. 실제 의미가 맞는 추가 관계가 필요한 후보만 `read-chunk --checkpoint <checkpoint> --source-sense-id <정확한 sense ID> --candidate <정확한 후보 문자열> --out .warroom-scratch/active-link-chunk.json`으로 한 후보씩 조회하고, 조회 결과가 가리키는 revision chunk의 추가 Relation만 저장한다. optional link가 불필요하면 새 판정을 만들지 않는다.

그 다음 `merge --checkpoint .warroom-scratch/relation-admission-{{shard}}-{{batch}}-{{part}}.json`과 정확한 `verify --shard {{shard}} --batch {{batch}} --part {{part}}`를 실행한다. 검증을 통과하면 기존 Relation/Drop 파일에 누적된 결과를 보존한 채 현재 브랜치에서 commit/push하고 이 Part의 PR 하나만 만든다. **Stage 2 PR에는 `batch` 라벨을 붙이지 않는다.** 같은 샤드의 열린 Stage 2 PR이 없는지 확인한다. PR 본문에서 #927을 참조하거나 닫지 않는다.

PR 제출 후 종료한다. 리뷰·머지 감시와 머지 후 master 검증은 War Room이 담당한다. 다른 모델·CLI·서브에이전트를 실행하지 않는다.
