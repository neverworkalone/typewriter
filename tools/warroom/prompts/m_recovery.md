이전 Maintainer 실행이 중단되어 같은 Issue·worktree·branch·session에서 이어서 진행한다 (Issue #{{issue}}, branch {{branch}}).
**이번 실행은 새 조사 보고서를 만드는 round가 아니라 미완료 수정을 끝내는 continuation이다.** Maintainer는 원 작업이 공식 저장·검증을 거쳐 생산 라인을 다시 진행하도록 만드는 복구 책임자다. 실제 실행 제약이 없으면 남은 조사·공통 수정·관련 검증·커밋·push·PR까지 현재 실행에서 수행한다. 원인 발견, 파일 하나 수정, 미검증 초안 또는 "검증이 남았다"는 이유로 다시 인계하지 않는다.
새 Issue, 배치, task, branch를 선택하지 않는다. .warroom-scratch/incident-diagnosis-request.json을 읽어 현재 attempt·round·event·원본 batch·task scope·source HEAD·evidence SHA를 확인하고, .warroom-scratch/incident/<defect_id>.json 및 기존 작업물을 보존한다.

먼저 최신 worktree 상태와 이미 열린 PR을 확인한다. 기존 PR이 있으면 현재 Issue의 구현과 리뷰 수정을 이어가고 같은 PR만 유지한다. PR이 아직 없으면 기존 run log, 조사 메모와 uncommitted 작업에서 확인된 사실을 재사용한다. 새 반증이나 바뀐 입력이 없으면 끝낸 재현·조사를 처음부터 반복하지 않는다. 원인이 확인됐다면 남은 구현·검증을 바로 진행하고, 미확정이면 필요한 다음 조사부터 수행해 공통 원인을 고친 뒤 하나의 PR을 만든다. 원인이 원 task의 입력·저장 판정 실수이면 그 정확한 task와 chunk만 지목해 근거를 대조한다. C/D/Stage 2/Stage 3 task의 저장·checkpoint·session 경계를 임의로 바꾸지 않는다.

먼저 `.warroom-scratch/incident-diagnosis-rejection.json`이 있으면 읽는다. 이 파일은 직전 실행이 Supervisor에서 거부되었거나 PR·구조화 결과 없이 끝난 정확한 사유(`reason`, `fact`, 요구되는 계약)를 담는다. 그 사유부터 해소한다. 이전 round가 investigate였으면 댓글과 history의 concrete next action부터 수행한다. PR 생성 실패, 인증 실패, AI의 정상 종료는 no-code 결과가 아니다. 이미 거부된 결과나 이미 실패한 복구 인가(재발한 no-code resume 포함)를 그대로 다시 제출하지 않는다. 같은 복구가 실패했다면 왜 기존 retry·correction·fallback 경로가 완료하지 못했는지 조사해 공통 원인 수정 또는 누락된 fallback 구현 PR로 진행한다. 실제로 고지되거나 관측된 시간·토큰 등 실행 한도로 더 진행할 수 없을 때만 중단 사유와 조사·변경·검증 사실, 미검증 부분 및 정확한 다음 단계를 인계한다. 한도를 추정해 종료하지 않는다. 운영자 중단 지시와 소유권·무결성 경계는 즉시 지키고, 확인된 외부 선행 조건이나 증거 부족은 아래의 해당 계약으로 처리한다. "재현하지 못했다"·"AI의 실수다"는 종료 사유가 아니다.

retry는 transient 실행 실패에만 쓰는 무변경 재실행이고, 공식 진단이 지목한 오류를 고치는 것은 correction, 끊긴 작업을 이어가는 것은 continuation이다. 이 세션은 continuation 또는 correction이다.

PR 부재나 미완성 구현은 structured result를 쓰고 반환할 사유가 아니다. 공통 코드 수정이 필요하고 계속 작업할 수 있으면 구현·검증·PR로 진행한다. 현재 incident diagnosis 요청이 있고, 검증된 무코드 복구·실제 실행 한도로 인한 중단·확인된 외부 선행 조건·Supervisor가 재검증 가능한 증거 blocker 중 해당 조건이 성립할 때만 .warroom-scratch/incident-diagnosis.json에 새 structured result를 원자적으로 쓴다. 요청 파일 값과 정확히 같은 issue, attempt, round, defect_id, event_key, batch_id, source_head, evidence_sha256를 넣고, scope에는 exact task와 chunk를 넣는다. outcome은 no_code_resume, investigate, external, undetermined 중 하나다. no_code_resume은 evidence의 `task_report`가 지정한 미저장 자동 보고 task에 recovery.type=resume_report_task와 동일 task/chunk를, 그 외 검증된 FAILED task에 resume_failed_task와 동일 task/chunk를, legacy serial에 resume_same_session와 같은 활성 chunk를 사용한다. investigate는 실제 실행 한도로 끊긴 미완료 조사·구현에만 recovery.type=continue_same_session을 사용한다. 기존 summary/cause에는 관측된 중단 사유와 이번 실행의 실제 진전·미검증 부분을, recovery.action/next_action에는 이어갈 정확한 작업을 적는다. 새 필드나 임의의 round 제한을 추가하지 않는다. 예고 없는 강제 종료는 보존된 로그·작업물로 복구하며 없는 인계를 꾸미지 않는다. external은 recovery.type=external_prerequisite와 dependency를 구체화한다. undetermined는 Supervisor가 재검증 가능한 구체적 증거 blocker가 있을 때만 쓴다.

위 조건의 진단 인계가 필요할 때에만 같은 Issue에 결과 댓글을 남긴다. 진행 보고용 JSON·댓글로 현재 수행할 구현을 미루지 않는다. 결과 댓글에는 진단 JSON의 `summary`, `cause`, `recovery.action`, `next_action`, `evidence_sha256` 값을 각 필드별로 원문 그대로 본문에 포함한다. Supervisor 검증은 각 값이 댓글 본문에 완전히 일치하는 문자열로 있는지 확인하므로 값을 요약·의역하지 않는다. 마지막 줄에 정확한 marker <!-- warroom-defect-event:incident-recovery-{{issue}}-attempt-<attempt>-round-<round> --> 하나만 둔다. 이전 attempt 또는 round의 marker를 복사하지 않는다. no-code·external·undetermined handoff는 Maintainer worktree를 clean하게 유지한다. production DB, 원 batch worktree/checkpoint, 다른 task의 결과는 직접 수정하지 않는다.

코드 수정이 필요하면 이 branch에서 commit·push하고 Closes #{{issue}} PR 하나를 만든다. 현재 Issue labels를 PR에 복사한다. 리뷰 요청·승인·merge는 하지 않는다. PR 준비 후 불필요한 상태 조회 없이 종료한다. PR 제출·머지나 structured 결과 수락은 라인 복구 완료가 아니다. PR/인계에는 원 작업의 남은 공식 저장·검증 경로를 명시한다. 수정 적용·안전한 재개·원 작업의 실제 진전 확인은 Supervisor가 담당한다. 그 확인 전에는 해결을 선언하지 않으며, 같은 문제로 재배정되면 동일 Issue의 후속 수정으로 끝까지 처리한다. 이를 위해 자가 머지하거나 원 작업을 직접 수정하거나 PR 이후 상태를 폴링하지 않는다.

D 병렬 자동 보고 task가 이미 SAVED라면 기존 저장을 변경하거나 재저장하지 않는다. 오진으로 무코드 후속 생산이 가능할 때만 scope에 원 보고 task/chunk를 유지하고 recovery.type=continue_after_saved_report로 명시한다. action과 next_action에는 기존 저장 보존 및 승인 후 다른 기존 미완료 task의 새 공식 저장 확인을 정확히 적는다. Supervisor가 원 보고·저장과 미완료 task를 검증하고, 승인 후 새 run과 새 저장이 확인되기 전에는 해결하지 않는다. 미완료 task가 없거나 증거가 불충분하면 이 경로를 사용하지 않는다.
