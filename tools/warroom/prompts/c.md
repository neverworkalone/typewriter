#1155 C 진행해

War Room이 지정한 배치 {{batch}}를 생산한다.
현재 worktree와 브랜치 {{branch}}를 그대로 사용한다.
배치를 다시 선정하거나 브랜치를 변경하지 않는다.
War Room이 준비한 HEAD를 기준으로 작업하며, 
생산 도중 master가 갱신되어도 현재 브랜치를 merge/rebase/reset하지 않는다.

Issue #1155의 C 생산 계약을 읽고 준수한다.

문학 검색 등 임시 작업은 가급적 포그라운드에서 실행하고 해당 실행의 종료 코드로 완료 여부를 확인한다.
진행 내용은 #1155의 로컬 ledger·체크포인트로 확인하되, 진행 기록만으로 프로세스 종료를 단정하지 않는다.
프로세스 상태 확인을 위해 시스템 전체를 조회하는 `ps`·`pgrep`을 호출하지 않는다.
백그라운드 실행이 불가피하면 해당 작업의 종료 상태를 `.warroom-scratch/`에 기록하여 그 작업만 추적한다.
종료 여부가 불명확하면 같은 검색 작업을 중복 실행하지 말고 현재 상태와 미확인 사항을 보고한다.
별도 프로세스 관리 프레임워크를 만들지 않는다.

Candidate v1 검증 후 커밋·push하고 `batch` 라벨의 PR을 제출한다.
PR 생성 직전 다른 모델을 포함한 동일 C 배치의 중복 점유를 확인한다.
PR 본문에는 `Refs #1155`만 사용한다.

PR 제출 후 종료한다.
리뷰·머지 감시와 다음 배치 실행은 War Room이 담당한다.
다른 모델·CLI·서브에이전트를 실행하지 않는다.

임시·스크래치 파일(검증용 스크립트, 청크, probe 결과 등)은 worktree 안의 `.warroom-scratch/` 에만 만든다. 이 디렉터리는 git에서 무시되며 커밋하지 않는다.
산출물이 아닌 파일을 worktree의 다른 경로에 남기지 않는다.
